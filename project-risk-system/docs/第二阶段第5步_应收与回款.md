# 第二阶段第5步：应收与回款

## 1. 完成结论

“应收与回款”页签已由静态原型升级为真实业务页面。系统从项目清单、有效风险和
已确认关联的补充回款数据中生成汇总、项目列表和详情，不再使用原型演示金额。

本步骤复用现有 `Project`、`Risk` 和 `SupplementalCollectionRow` 数据模型，
没有新增数据库表或迁移。数据库现有7个迁移均已应用。

## 2. 功能范围

### 2.1 汇总与筛选

- 仅统计当前存在有效风险的项目；
- 展示风险项目数、高风险项目数、待回款总额和金额完整项目数；
- 支持按项目名称/编码、风险等级和项目负责人筛选；
- 所有数量按项目去重，高风险项目数不是高风险记录数。

### 2.2 项目回款列表

列表展示：

- 项目名称、项目编码、交付部门和负责人；
- 当前最高有效风险等级及有效风险数量；
- 计划金额、已回款和剩余待回款；
- 下一笔回款及其来源；
- 原始回款进展；
- 金额数据来源和更新时间。

### 2.3 项目回款详情

点击项目后可查看：

- 计划金额、已回款和完成率；
- 待回款、下一笔回款、回款进展、统计口径和更新时间；
- 1—12月月度回款，区分实际、预计/计划及未提供；
- 当前项目的全部有效风险，包括等级、类别、描述、来源和上报时间。

详情弹框与既有部门回款弹框保持一致，金额重点突出，最小字体不低于12px。

### 2.4 响应式适配

- 桌面端使用横向数据表；
- 手机端自动转换为单列项目卡片，不再压缩成多列窄字；
- 详情弹框在手机端使用双列月份网格；
- 桌面端和390px手机端均无页面或弹框横向溢出。

## 3. 数据口径

### 3.1 项目范围

查询必须同时满足：

1. 用户拥有 `dashboard.view` 权限；
2. 项目位于用户可访问的数据范围内；
3. 项目当前至少存在一条有效风险。

### 3.2 金额来源

金额按以下优先级解析：

1. 项目清单中计划金额、已回款和剩余待回款三项完整时，使用项目清单；
2. 项目清单不完整时，仅使用已由管理员确认关联的补充回款记录；
3. 两类来源均不完整时返回空值，前端显示“待补充”。

空白金额不等于0，未匹配的“涵谷回款”记录不进入任何项目或部门统计。

### 3.3 下一笔回款

1. 优先取当前月份及以后，属性为“预计”或“计划”且金额大于0的最早月份；
2. 无有效月度计划时，回退展示项目的原始回款进展文本；
3. 两者均不存在时显示“待补充”。

系统不从描述中推算金额，不补造日期。

### 3.4 风险等级

列表风险等级取项目全部有效风险中的最高等级；同一项目有多条高风险时仍只计为
一个高风险项目。

## 4. 接口与权限

### 4.1 接口

- `GET /api/dashboard/collections`
  - 参数：`keyword`、`level`、`owner`；
  - 返回：汇总、筛选项和风险项目回款列表。
- `GET /api/dashboard/collections/:projectId`
  - 返回：项目元数据、回款汇总、12个月月度数据和全部有效风险。

### 4.2 安全边界

- 两个接口均由后端校验 `dashboard.view`；
- 查询统一应用当前用户项目数据范围；
- 无权访问的项目不会通过详情ID绕过范围校验；
- 金额来源、统计口径和更新时间随详情一并返回。
