# 第三阶段第5步：风险管理员个人邮箱配置真实后端实现说明

## 1. 实现范围

本步骤以 `ui-prototype/10-mailbox-settings.html` 为唯一功能和界面基准，完成风险管理员个人邮箱配置的真实后端开发，不删减原型功能，不重新设计页面布局：

- 仅风险管理员配置、测试、启停和同步本人邮箱。
- QQ 邮箱与通用 IMAP 参数配置。
- 邮箱授权码加密保存、更新不回显、页面不保存明文。
- 真实 IMAP 登录、加密连接和文件夹读取测试。
- 主题关键词、发件人、首次同步范围、附件读取和 AI 风险提取规则。
- 连接状态、最近测试、最近同步、自动同步和凭据保护概览。
- 停用确认、恢复邮箱、手动同步入口和同步结果页入口。
- 保存、测试、启停、同步任务创建的审计记录。

## 2. 数据结构与迁移

迁移：`apps/api/prisma/migrations/20260803000300_mailbox_config_management/migration.sql`

新增 `mailbox_configs`：

- 每个用户只能有一份个人邮箱配置，删除用户时级联删除配置。
- 保存服务商、邮箱、IMAP 主机、端口、加密方式、文件夹和识别规则。
- 保存连接测试、同步游标、最近同步统计和启停状态。
- 授权码拆分保存为 AES-256-GCM 密文、IV 和认证标签。

新增 `mail_sync_batches`：

- 记录手动、定时和重试触发来源。
- 记录队列、运行、成功、部分成功、失败及取消状态。
- 记录处理、成功、失败、风险线索数量和安全错误摘要。
- 本步骤只创建真实排队任务；邮件拉取、解析和风险确认由第三阶段第6步实现。

## 3. 权限与本人隔离

- `mailbox.manage_self`：读取、保存、测试、启停本人邮箱。
- `mailbox.sync_self`：创建本人邮箱同步任务。
- 服务端除权限校验外，再强制校验当前角色为风险管理员。
- 所有查询和写入使用会话中的用户 ID，不接受前端传入目标用户 ID。
- 系统管理员不能代配授权码，也不能测试或同步其他人的邮箱。

## 4. API

- `GET /api/mailbox/me`
- `PUT /api/mailbox/me`
- `POST /api/mailbox/me/test`
- `POST /api/mailbox/me/status`
- `POST /api/mailbox/me/sync`

读取接口只返回掩码邮箱、`hasAuthCode` 和运行状态，不返回授权码明文、密文、IV 或认证标签。更新请求不提交授权码时沿用已保存凭据。

## 5. IMAP 连接与安全

- 使用 `imapflow` 建立真实 IMAP 连接并打开只读文件夹。
- 支持 SSL/TLS 与 STARTTLS，最低 TLS 1.2。
- 设置连接、问候、Socket 和认证超时，禁用协议原始日志。
- 在连接前解析 DNS，拒绝本机、环回、链路本地、私网及保留地址，降低 SSRF 和 DNS 重绑定风险。
- 对认证、文件夹、TLS、超时和不可达错误进行安全分类，不向页面返回底层堆栈或服务器敏感信息。

## 6. 正式页面

正式入口：`http://localhost:5173/mailbox-settings`

页面保留原型中的角色边界提示、四项运行概览、邮箱类型、账号与服务器、QQ 开启说明、周报识别规则、同步控制、五步数据流、安全说明和停用弹框。所有状态和操作来自真实 API；授权码保存后立即清空，页面不回显。

页面同时修正了未配置状态文案：首次进入时明确显示“尚未配置 / 尚未保存配置”，不会把账号资料中的邮箱误标为已保存的邮箱配置。

## 7. 审计与数据保护

- `MAILBOX_CONFIG_SAVED`
- `MAILBOX_CONNECTION_TESTED`
- `MAILBOX_ENABLED`
- `MAILBOX_DISABLED`
- `MAILBOX_SYNC_QUEUED`

审计快照只包含邮箱掩码、连接参数和业务规则，不包含授权码、完整邮箱正文、附件或会话信息。实库核验确认授权码密文、IV 和认证标签均已生成，审计记录未出现测试明文。
