# 第三阶段第4步：审计日志真实后端实现说明

## 1. 实现范围

本步骤以 `ui-prototype/09-audit-logs.html` 为唯一功能与界面基准，完成审计日志页面的真实后端开发，不删减原型内容，不重新设计页面结构：

- 今日操作、失败记录、敏感操作、活跃操作人实时汇总。
- 按关键词、模块、操作类型、执行结果、日期范围和自定义日期筛选。
- 服务端分页、动态筛选项及真实记录总数。
- 事件详情、资源 ID、Trace ID、客户端、执行说明、前后快照和哈希摘要。
- SHA-256 只追加哈希链完整性校验。
- Excel / CSV 受控导出、导出原因必填及导出行为二次审计。
- 数据范围和权限控制；敏感字段、邮箱和客户端 IP 脱敏。

## 2. 数据结构与不可篡改约束

迁移：`apps/api/prisma/migrations/20260803000200_audit_log_management/migration.sql`

`audit_logs` 新增：

- `summary`：可检索的业务摘要。
- `is_sensitive`：敏感操作标记。
- `previous_hash`：上一条日志的完整性哈希。
- `integrity_hash`：当前记录的 SHA-256 哈希。

PostgreSQL 触发器在插入时串行计算哈希链，并拒绝对审计日志执行 `UPDATE` 或 `DELETE`。历史记录已完成哈希回填，完整性接口会逐条复算并返回异常位置。

## 3. 权限

- `admin.audit.view`：查看汇总、筛选项、列表、详情及完整性状态。
- `admin.audit.export`：导出筛选结果；首版仅分配给系统管理员。
- 非系统管理员即使具有查看权限，也只返回其项目授权范围内的资源审计记录。

## 4. API

- `GET /api/admin/audit-logs/summary`
- `GET /api/admin/audit-logs/options`
- `GET /api/admin/audit-logs/integrity`
- `GET /api/admin/audit-logs`
- `GET /api/admin/audit-logs/:id`
- `POST /api/admin/audit-logs/export`

导出接口最多生成 10,000 条记录，要求至少 4 个字符的业务用途，不输出前后快照、密码、授权码、API Key 或未脱敏客户端 IP。成功或失败的导出操作均追加审计记录。

## 5. 正式页面

正式入口：`http://localhost:5173/admin/audit-logs`

页面已恢复原型中的安全说明、四项指标、筛选区、日志表格、分页、详情弹框、完整性状态和受控导出弹框。所有数据来自真实 API；可见字号不低于 12px，桌面与移动断点沿用原型结构。

## 6. 数据保护

- 密码、访问令牌、授权码、API Key、Cookie、邮件正文及 AI 原始响应不会返回页面。
- 邮箱地址仅显示掩码，客户端 IPv4 仅保留前两段。
- `passwordMinLength`、`sessionHours` 和 `colorToken` 等非密钥策略字段保留可读值，避免过度脱敏。
- 数组对象在摘要中显示项目数量，详情区保留脱敏后的完整 JSON，避免出现 `[object Object]`。
