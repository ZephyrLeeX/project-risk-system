# 第二阶段第1步：项目清单 Excel 导入

## 1. 交付结论

本步骤已实现项目清单 Excel 从上传预检到确认入库、批次查询和安全回滚的完整闭环。
实现以真实文件“项目清单.xlsx”为验收样本，不改变工作簿现有业务模块。

当前主数据工作表为“数据回款”；“涵谷回款”作为补充回款数据独立解析和保存；
“发函-诉讼清单”作为法务事项独立解析、匹配并关联项目。两类附属数据都不会
被误合并为项目主数据，“汇总”仅保留为来源元数据。

## 2. 业务规则

### 2.1 文件和工作表

- 仅接收扩展名为 `.xlsx` 且内容具有有效 ZIP/Excel 文件签名的文件；
- 单文件上限20MB；
- 必须存在“数据回款”工作表；
- 第3行为字段标题，第4行起为项目数据；
- 第2行保存1月至12月的“实际/预计”等月份属性；
- 空白金额保持 `NULL`，不自动转换为0；
- 单元格颜色仅作为来源快照，不作为金额或风险判断的唯一依据。

### 2.2 项目匹配

- 有项目编码时优先使用规范化后的项目编码生成导入键；
- 项目编码为空时，使用项目名称、交付部门和交付负责人组合生成导入键，并产生警告；
- 已匹配项目标记为更新，未匹配项目标记为新增；
- 同一工作簿中的重复组合键会附加行号形成独立导入键并产生警告，避免静默覆盖。

### 2.3 校验和确认

- 交付部门、交付负责人和项目名称不能为空；
- 金额必须是有效数字；
- 年度计划不等于实际已回款与剩余待回款之和时产生警告；
- 存在错误行时禁止确认导入；
- 存在警告行时必须显式勾选“已阅读并确认警告”；
- 正式导入在数据库事务中完成，任意一行失败则整批回滚。

### 2.4 批次回滚

- 只有状态为“已导入”的批次可以回滚；
- 如果相关项目已经被更晚批次更新，则禁止直接回滚；
- 本批次新增项目在回滚时删除；
- 本批次更新项目按导入前快照恢复；
- 无用户和项目引用的导入临时部门会被清理；
- 预检、确认和回滚操作均写入审计日志。

### 2.5 涵谷回款补充数据

- 第2行为字段标题，第3行起为补充回款记录；
- 读取合同应收金额、采购合同总额、累计已收款额等隐藏列，不因列隐藏而漏数；
- 读取1月至12月回款、月份实际/计划属性及“26年以后”金额；
- 优先按项目编码、其次按规范化后的项目名称精确匹配主项目；
- 匹配结果分为已匹配、待匹配和多项匹配；
- 未匹配记录仍可在管理员确认警告后独立入库，但不会创建主项目，也不改变项目总数；
- 补充记录随所属批次一起确认和回滚。

### 2.6 发函与诉讼事项

- 第3行为字段标题，第4行起为法务事项；
- 读取交付部门、交付负责人、项目编码、项目名称、年度计划、1月至12月回款、
  回款风险和回款进展；
- 优先按项目编码、其次按规范化后的项目名称精确匹配主项目；
- 匹配结果分为已匹配、待匹配和多项匹配，缺少项目编码时保留警告；
- 已匹配事项在确认导入后关联对应项目，不重复创建项目；
- 未匹配或多项匹配事项允许在管理员确认警告后独立保存，等待后续人工关联；
- 法务事项随所属批次一起确认和回滚。

## 3. 数据模型

### 3.1 Project 扩展

- `importKey`：稳定导入匹配键；
- `deliveryOwnerName`：交付负责人姓名；
- `annualPlanAmount`：年度计划回款；
- `actualCollectedAmount`：实际已回款；
- `remainingAmount`：剩余待回款；
- `monthlyCollections`：1月至12月金额、属性和来源颜色；
- `monthAttributes`：月份实际/预计属性；
- `collectionRiskLevel`：高、中、低或未知；
- `collectionProgress`：回款进展；
- `lastImportedAt`：最近导入时间。

### 3.2 ImportBatch

记录文件名、哈希、存储位置、预检统计、状态、上传人、确认人、回滚人及各阶段时间。

### 3.3 ProjectImportRow

记录源行号、新增/更新动作、校验状态、逐字段解析结果、警告和错误、匹配项目、
提交项目、导入前快照与导入后快照。

### 3.4 SupplementalCollectionRow

记录“涵谷回款”源行、匹配状态、关联项目、隐藏金额字段、月度回款、风险等级、
来源快照、警告和错误。未匹配记录允许 `projectId` 为空，等待后续人工关联。

### 3.5 LegalMatterRow

记录“发函-诉讼清单”源行、匹配状态、关联项目、月度回款、风险等级、法务进展、
来源快照、警告和错误。匹配主表待新增项目时先保存导入键，确认后再建立项目关联。

## 4. API

所有接口需要有效会话和 `admin.import.manage` 权限。

| 方法 | 地址 | 说明 |
| --- | --- | --- |
| POST | `/api/imports/project-list/preview` | multipart 上传并预检，字段名为 `file` |
| GET | `/api/imports/project-list/batches` | 分页查询批次 |
| GET | `/api/imports/project-list/batches/:id` | 查询批次和逐行结果 |
| POST | `/api/imports/project-list/batches/:id/confirm` | 确认导入，提交 `acknowledgeWarnings` |
| POST | `/api/imports/project-list/batches/:id/rollback` | 回滚已导入批次 |

## 5. 前端页面

路由：`/admin/imports`

页面包含：

- 拖拽或点击选择 Excel；
- 文件类型和大小提示；
- 预检汇总卡片；
- 错误和警告提示；
- 警告确认勾选；
- 131行逐行预览与新增/更新状态；
- “涵谷回款”记录数、已匹配、待匹配、多项匹配和错误统计；
- 16条补充回款逐行预览、金额字段及匹配信息；
- “发函-诉讼清单”记录数、匹配和错误统计；
- 2条法务事项逐行预览、风险等级、进展和关联状态；
- 导入批次历史；
- 批次详情；
- 安全回滚操作。

页面沿用后台管理视觉体系，并包含移动端断点适配，界面最小字体不低于12px。

使用真实“项目清单.xlsx”执行了可自动清理的端到端验收：

- 健康检查和数据库连接成功；
- 解析131行；
- 解析“涵谷回款”16条记录，并读取隐藏金额列；
- 16条记录均未与主表精确匹配，按待匹配记录保留，未新增项目；
- 解析“发函-诉讼清单”2条法务事项；
- 2条法务事项均精确匹配主表项目，确认后建立关联且未重复创建项目；
- 可导入1行、警告130行、错误0行；
- 未确认警告时接口正确拒绝导入；
- 确认后新增131个项目；
- 风险分布：高风险27个、中风险24个、低风险80个；
- 空白金额仍为 `NULL`；
- 批次详情和历史查询正确；
- 回滚后项目数量恢复到验收前基线；
- 131条逐行记录均进入已回滚状态；
- 16条补充回款记录均进入已回滚状态；
- 2条法务事项均进入已回滚状态；
- 390×844手机视口无页面级横向溢出，宽表在独立容器内滚动；
- 浏览器控制台无警告或错误；
- 临时导入部门、测试批次、测试文件、会话和测试审计记录已自动清理。

## 7. 运维配置

- `IMPORT_STORAGE_DIR`：原始 Excel 文件根目录，默认 `storage/excel`；
- 数据库迁移：`20260728000100_project_import_foundation`；
- 补充回款迁移：`20260730000100_supplemental_collection_import`；
- 发函诉讼迁移：`20260730000200_legal_matter_import`；
- 部署前执行 `pnpm --filter @risk-platform/api exec prisma migrate deploy`；
- 生产环境应将导入目录挂载到持久化存储，并纳入备份与访问控制策略。
