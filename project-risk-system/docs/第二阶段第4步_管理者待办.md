# 第二阶段第4步：管理者待办

## 1. 完成结论

本步骤已将原型中的“管理者待办”升级为真实业务模块。待办由有效风险自动形成，
支持数据范围过滤、负责人和状态筛选、智能日程、完整详情、受权限控制的处理更新、
审计留痕及导入批次回滚。

本步骤没有新增或改变原有业务模块，仅将既有页签接入真实数据并完善交互与响应式布局。

## 2. 数据模型

新增 `ActionItem` 待办实体，与风险保持一对一关系，并关联项目、创建人、责任人和完成人。

核心字段包括：

- 紧急度：`EMERGENCY`、`HIGH`、`NORMAL`；
- 状态：`PENDING`、`IN_PROGRESS`、`COMPLETED`；
- 来源：`RISK_SUGGESTION`、`MANUAL`；
- 待办标题、说明、责任人名称及用户关联；
- 截止日期、完成时间、完成说明；
- 创建人、完成人和标准审计时间戳。

数据库迁移：`apps/api/prisma/migrations/20260731000100_manager_action_items/migration.sql`。
迁移会为既有有效风险补齐待办，并通过风险唯一约束防止重复生成。

## 3. 自动生成规则

项目清单确认导入时，系统在风险入库后同步创建或更新对应待办：

- 高风险映射为“紧急”；
- 中风险映射为“高”；
- 低风险和待确认风险映射为“普通”；
- 高风险默认责任人为“管理者”；
- 其他风险优先采用项目负责人，缺失时采用“管理者”；
- 待办标题由项目名称和风险类别组成；
- 待办说明采用风险建议措施，不足时回退到风险描述。

再次导入相同风险时，只刷新风险内容和紧急度，不覆盖人工调整的负责人、状态、
截止日期和处理说明。批次回滚时，待办随风险快照同步恢复或删除。

## 4. 接口设计

### 4.1 查询列表

`GET /api/todos?owner=&status=`

返回：

- 待办列表；
- 待处理、处理中、已完成和紧急待办汇总；
- 根据截止日期、紧急度和更新时间生成的本周日程建议，最多5项。

### 4.2 查询详情

`GET /api/todos/:id`

返回待办完整字段、项目信息及关联风险的等级、类别、描述、证据、建议措施和来源。

### 4.3 更新处理

`PATCH /api/todos/:id`

支持更新：

- 负责人；
- 状态；
- 截止日期；
- 处理说明。

状态变为已完成时记录完成人和完成时间；重新打开时清除完成信息。

## 5. 权限与数据范围

- 列表和详情要求 `dashboard.view`；
- 更新要求 `risk.resolve`；
- 后端通过现有 `DataScopeService` 执行项目数据范围过滤；
- 无权更新的账号在详情弹框中只读展示，不渲染保存按钮；
- 所有更新写入 `ACTION_ITEM_UPDATED` 审计日志。

权限校验以后端为最终边界，前端只用于交互提示和控件状态。

## 6. 页面与响应式设计

页面保留原“管理者待办”页签，包含：

- 四项状态汇总；
- 本周智能日程；
- 负责人和状态筛选；
- 待办明细表；
- 完整详情及处理弹框。

桌面端使用表格展示；宽度不超过900px时自动转为卡片布局；390px手机视口下，
汇总、日程、筛选和详情弹框均无横向溢出。页面及弹框最小有效字号为12px。
