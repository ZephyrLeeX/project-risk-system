# 第三阶段第3步：系统配置真实后端实现说明

## 1. 实现范围

本步骤以 `ui-prototype/08-system-config.html` 为功能基准，不新增或删除原型模块，完成以下能力的真实持久化与页面串联：

- 风险类别：新增、编辑、启停、排序、颜色、说明、关键词和默认等级。
- 风险等级：固定高、中、低三级，维护颜色、处理口径和提示词。
- 周报与邮箱同步：同步周期、首次同步范围、主题关键词和正文风险标记。
- 项目别名：只映射到已有项目，支持多个别名、启停、来源和备注。
- 会话与登录：会话有效期、空闲退出、失败锁定阈值、锁定时长和密码最小长度。
- 后台提醒：邮箱失败、API Key 到期、Excel 导入失败和异常登录。
- 配置版本：保存并发布、放弃草稿、变更历史、版本详情和影响范围。
- 审计：成功发布在同一事务中写入审计；业务发布失败写入失败审计。

## 2. 数据结构

迁移：`apps/api/prisma/migrations/20260803000100_system_config_management/migration.sql`

- `system_config_releases`：只追加的配置版本、前后快照、变更摘要、影响范围、发布人和 Trace ID。
- `risk_level_rules`：高、中、低三级风险规则。
- `project_aliases`：项目与标准化别名映射。
- `risk_categories`：新增颜色、说明和默认等级字段；已有风险关系保持不变。

初次读取会生成 V12.3 基线版本；后续每次成功发布自动递增次版本号。

## 3. API

全部接口要求登录、`admin.config.manage` 权限，并受统一 CSRF 来源校验保护。

- `GET /api/admin/system-config`：当前生效配置、指标和完整快照。
- `GET /api/admin/system-config/project-options`：项目别名可选择的真实项目。
- `POST /api/admin/system-config/publish`：事务发布全部配置并生成版本。
- `GET /api/admin/system-config/releases`：版本历史，可按模块过滤。
- `GET /api/admin/system-config/releases/:id`：版本前后快照、影响范围和审计 Trace ID。

## 4. 运行时生效

安全参数不只保存在页面：登录创建新会话、登录失败锁定和修改密码时，认证服务会读取最新发布版本中的安全配置；现有会话按原到期时间结束，符合原型说明。

## 5. 正式页面

正式入口：`http://localhost:5173/admin/system-config`

页面已接入真实数据，并保留原型的七个配置分区、顶部指标、配置目录、草稿提示、发布确认、放弃确认和历史详情。发布请求会剥离风险数量、项目名称等只读展示字段，避免展示模型和写入模型混用。

- 配置快照不保存邮箱授权码或 API Key 明文。

- 项目别名不能重复，且必须指向已有项目。
- 高、中、低三级规则必须完整。
