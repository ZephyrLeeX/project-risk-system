- 本步骤性质：只读核查与设计清单，不修改页面布局、不新增业务模块、不执行数据库迁移

## 1. 强制实施原则

1. 11个HTML原型是正式系统页面布局、功能入口、弹框内容和字段顺序的唯一基准。
2. 后续开发只允许把模拟数据替换为真实数据、补齐接口与持久化、修复缺陷及响应式适配；不得自行删减、合并或改版页面模块。
3. 风险管理员只能配置和同步本人邮箱；系统管理员不得代配授权码，也不得读取邮件正文、附件或授权码。
4. API Key、邮箱授权码必须加密存储，任何列表、详情、审计和错误日志均不得返回明文。
5. 审计记录只追加，不提供修改和删除能力；敏感字段仅保存脱敏摘要。
6. 所有新增接口继续使用现有会话认证、CSRF来源校验、RBAC权限和统一响应结构。

## 2. 核对结论

正式系统已经具备11个页面路由，但“页面存在”不等于“业务真实化完成”。当前状态如下：

| 状态 | 页面数量 | 页面 |
| --- | ---: | --- |
| A：核心闭环已真实化 | 3 | 01登录、04用户管理、06项目数据导入 |
| B：主要数据真实，仍含模拟区块 | 3 | 02风险看板、03管理概览、05角色权限 |
| C：页面已接入，业务仍为前端模拟 | 5 | 07 API Key、08系统配置、09审计日志、10个人邮箱、11邮箱同步结果 |

最关键的事实：

- API工程目前没有AI服务、系统配置、邮箱配置或邮箱同步模块。
- Prisma目前没有AI服务、系统配置版本、项目别名、邮箱配置、邮件、同步批次或AI风险线索数据表。
- `audit_logs` 表和审计写入服务已经存在，但没有全局审计查询、详情、汇总和受控导出接口。
- 第7～11页目前直接在Vue组件中使用静态数组、`setTimeout`和本地变量模拟保存、测试、同步、筛选及导出。
- 第2、3、5页仍有静态区域，必须在第7～11页后端完成后回接真实数据。

### 6.1 新增/调整数据结构

1. `system_config_releases`
   - `id`、`version`、`snapshot`、`changeCount`、`changeSummary`、`impactScope`
   - `publishedById`、`publishedAt`、`createdAt`
   - 每次发布保存完整脱敏快照，版本号唯一且只追加。
2. `risk_level_rules`
   - `level`、`displayName`、`colorToken`、`criteria`、`enabled`、`sortOrder`。
3. 扩展`risk_categories`
   - 保留现有`code/name/keywords/isActive`，补充`colorToken`、`ruleDescription`、`defaultLevel`。

4. `project_aliases`
   - `id`、`projectId`、`alias`、`normalizedAlias`、`note`、`enabled`、`hitCount`、`lastHitAt`。
   - `normalizedAlias`唯一，避免一个别名映射多个项目。

发布必须使用单数据库事务：校验全部配置 → 写入规范化表 → 创建版本快照 → 写审计。任一环节失败则全部回滚。

| 失败邮件重新处理 | 仅显示提交成功 | `POST /mailbox/messages/:id/retry` | 邮件及新/原批次 | `mailbox.sync_self` | `MAIL_MESSAGE_RETRIED` |
| 忽略风险线索 | 正式页缺少原型操作 | `POST /mailbox/risk-candidates/:id/ignore` | `mail_risk_candidates` | 同时要求`mailbox.sync_self`和`risk.resolve` | `MAIL_RISK_IGNORED` |
| 调整后确认 | 正式页缺少原型操作 | `PATCH /mailbox/risk-candidates/:id`后确认 | `mail_risk_candidates` | 同上 | `MAIL_RISK_ADJUSTED` |
| 确认并发布到看板 | 正式页缺少原型操作 | `POST /mailbox/risk-candidates/:id/confirm` | 候选项、`risks`、时间线、待办 | 同上 | `MAIL_RISK_CONFIRMED` |
| 手动同步和进度反馈 | 定时器模拟 | `POST /mailbox/me/sync`并轮询批次 | `mail_sync_batches` | `mailbox.sync_self` | `MAILBOX_SYNC_STARTED` |

### 9.1 新增数据表

1. `mail_sync_batches`
   - `id`、`mailboxConfigId`、`triggerType`、`status`、`operatorUserId`
   - `startedAt`、`finishedAt`、`durationMs`
   - `scannedCount`、`newCount`、`successCount`、`skippedCount`、`failedCount`、`riskCandidateCount`
   - `startUid`、`endUid`、`errorSummary`。
2. `mail_messages`
   - `id`、`mailboxConfigId`、`batchId`、`messageId`、`imapUid`
   - `subject`、`senderName`、`senderAddress`、`sentAt`
   - `status`、`skipReason`、`failureCode`、`failureSummary`
   - `sanitizedSummary`、`attachmentMetadata`、`processingTrace`
   - `bodyEncrypted`可选；若业务无需回看原文则不落库正文，只保存脱敏摘要和证据片段。
3. `mail_message_project_matches`
   - `messageId`、`projectId`、`matchType`、`confidence`、`matchedText`、`confirmedById`。
4. `mail_risk_candidates`
   - `messageId`、`projectId`、`categoryId`、`level`
   - `description`、`evidence`、`suggestion`、`confidence`
   - `status`（待确认、已确认、已忽略）、`confirmedRiskId`
   - `reviewedById`、`reviewedAt`、`createdAt`、`updatedAt`。

### 9.2 数据隔离规则

- 所有邮箱查询必须强制追加`mailboxConfig.userId = 当前登录用户ID`，不能接受前端传入任意用户ID。
- 系统管理员只能从管理概览看到连接/运行状态统计，不得调用邮件详情接口。
- 邮件风险确认后生成`Risk.sourceType = MAIL_AI`，`sourceRefId`指向候选项，并同步创建时间线事件；是否生成待办继续使用现有风险规则。
- 同一邮箱、文件夹和UID不得重复处理；失败任务不得提前推进UID游标。

## 11. 权限补充决策

绝大多数页面可复用现有权限码，仅建议新增一个权限：

| 权限码 | 用途 | 默认授权 |
| --- | --- | --- |
| `admin.audit.export` | 导出审计日志 | 仅系统管理员；查看/审计员默认只查看，后续可由系统管理员显式授权 |
