# 第二阶段第2步：Web 风险看板

## 1. 本步目标

本步将原工程首页的阶段占位页替换为正式 Web 风险看板，并将项目清单
Excel 与“发函-诉讼清单”中的风险信息转为独立风险数据。页面、接口和数据库
均使用真实工程链路，不读取静态 HTML 原型中的演示数据。

既定六个业务模块保持不变：

1. 项目风险清单；
2. 部门回款汇总；
3. 管理者待办；
4. 应收与回款；
5. 风险时间线；
6. 已解除风险。

本步完成第一个模块的正式接入，其余模块保留原有入口并标记为后续接入，
没有删除或改名。

## 2. 数据模型

新增独立的风险分类和风险记录：

- `risk_categories`：分类编码、名称、关键词、启停状态和排序；
- `risks`：项目、分类、标题、描述、证据、等级、状态、来源、建议措施、
  周次、发现时间和解除信息；
- `dedupeFingerprint`：保证同一项目的同类导入风险可重复更新而不是重复堆积；
- `sourceBatchId`、`sourceRefId`：保留导入批次与源行追踪关系。

默认分类共8类：回款风险、发函诉讼风险、供应商风险、客户层面风险、
成本风险、验收延期风险、超出合同需求和其他风险。

项目导入行及法务事项行新增风险提交标识和前后快照。确认导入时项目和风险
在同一事务写入；批次回滚时先恢复或删除风险，再恢复或删除项目，保证数据一致。

对应数据库迁移：

`20260730000300_risk_dashboard_foundation`

## 3. Excel 风险映射

### 3.1 数据回款工作表

对每个风险等级不是“待确认”的项目生成一条回款风险：

- 分类：回款风险；
- 来源：项目清单 Excel；
- 标题：项目名称 + 回款风险；
- 描述：优先使用源表“回款进展”，为空时给出明确的待跟踪说明；
- 证据：保留工作表行号和源风险等级；
- 上报人：使用交付负责人源值；
- 建议措施：根据高、中、低等级生成不同的跟踪建议。

### 3.2 发函-诉讼清单

匹配到项目且风险等级有效时生成一条发函诉讼风险：

- 分类：发函诉讼风险；
- 来源：发函诉讼清单；
- 描述：使用法务进展原文；
- 证据：保留源工作表行号和风险等级；
- 建议措施：跟踪发函、协商、诉讼节点和责任人。

## 4. 后端接口

接口均需要登录并校验 `dashboard.view` 权限，同时使用现有项目数据范围服务。
越权的项目风险不会进入统计、列表或详情。

- `GET /api/dashboard/summary`：项目、风险、高风险及风险项目回款汇总；
- `GET /api/dashboard/focus`：本周重点风险；
- `GET /api/risks/options`：风险分类和当前数据范围内负责人选项；
- `GET /api/risks`：关键词、等级、分类、负责人筛选及分页；
- `GET /api/risks/:id`：完整风险详情和同项目其他风险。

金额以字符串形式返回，避免前后端浮点精度损失。源数据金额为空时接口返回
`null`，前端显示“数据待补充”，不使用演示数或推算数替代真实数据。

正式首页 `/` 包含：

- 产品导航、用户信息、后台管理入口和安全退出；
- 项目总数、风险总数、高风险、待回款、已回款5项指标；
- 本周重点关注；
- 六个既定业务页签；
- 风险关键词、等级、类别、负责人筛选；
- 风险列表、分页、完整详情弹框和同项目风险关联。

详情弹框完整展示风险描述、证据、建议措施、负责人、上报人、已回款、
待回款、发现时间和更新时间，没有删减已有详情信息。

## 6. 响应式与可读性

- 看板所有辅助文字最小为12像素；
- 桌面端采用指标卡、重点关注区和表格；
- 900像素及以下将风险表格转换为独立卡片；
- 620像素及以下改为单列筛选、单列指标卡和单列详情信息；
- 项目名称、类别和风险描述保留正常横向排版，不会被压成逐字竖排；
- 详情弹框在手机端限制为94%视口高度并独立滚动。
