# 第二阶段第3步：部门回款汇总

## 1. 交付结论

本步骤已将 Web 风险看板中的“部门回款汇总”页签接入真实数据库，并补齐
“涵谷回款”待匹配记录的人工关联和解除关联闭环。

项目清单、补充回款和部门统计继续使用现有业务模块，没有新增替代模块。
未匹配的补充回款记录不计入任何部门，避免把名称相似但未经确认的数据错误归属。

## 2. 数据口径

### 2.1 项目清单优先

项目清单 Excel 的年度计划、实际已回款和剩余待回款能够组成完整金额组时，
部门统计优先采用项目清单金额，避免与补充回款重复计算。

金额组中任意两项存在时，可按“应收 = 已收 + 未回”的恒等关系补齐第三项。
不足两项时保持数据缺失状态，不补造金额。

### 2.2 补充回款兜底

项目清单金额不完整、且存在已人工确认关联的“涵谷回款”记录时，采用：

- 合同应收金额作为应收；
- 累计已收款额作为已收；
- 原表有剩余未回款时直接采用；
- 原表剩余未回款为空、但应收与已收均存在时，按
  `剩余未回款 = max(合同应收金额 - 累计已收款额, 0)` 计算。

一个项目关联多条补充记录时按记录求和。未匹配和多项匹配记录只显示待处理数量
和待分配应收，不进入部门或全局合计。

### 2.3 数据范围

部门汇总与明细继续使用现有项目数据范围：

- 全部项目；
- 本人负责；
- 被授权项目；
- 本人负责及被授权项目；
- 无项目数据。

只有具备 `admin.import.manage` 权限的用户可以查看全局待匹配补充记录数量和金额，
并进入项目关联页面。

## 3. 人工项目关联

后台“项目数据导入”页在已导入批次的“涵谷回款记录明细”中新增：

- 显示当前关联主项目和部门；
- “关联项目”与“调整关联”入口；
- 131个当前有效主项目的选择列表；
- 确认关联；
- 解除关联；
- 操作后实时更新批次的已匹配、待匹配和多项匹配数量；
- 关联和解除均记录审计日志。

只有状态为“已导入”的补充记录允许调整。已回滚、预检中或目标项目已归档时，
接口拒绝操作。

## 4. 后端接口

所有部门回款接口需要有效会话和 `dashboard.view` 权限：

- `GET /api/dashboard/departments/collections`：部门汇总、全局合计及待匹配提示；
- `GET /api/dashboard/departments/:departmentKey/collections`：
  部门项目回款明细。

人工匹配接口需要 `admin.import.manage` 权限：

- `GET /api/imports/project-list/projects/options`：获取可关联主项目；
- `POST /api/imports/project-list/supplemental/:id/match`：确认或调整项目关联；
- `DELETE /api/imports/project-list/supplemental/:id/match`：解除关联。

## 5. 前端实现

“部门回款汇总”页签包含：

- 待匹配记录和待分配应收提示；
- 项目总数、已统计应收、累计已收、剩余未回及数据完整项目数；
- 部门项目数、金额、完成率和缺失项目数；
- 部门项目明细弹框；
- 每个项目的金额来源标识：项目清单 Excel、涵谷回款或数据待补充。

桌面端使用表格与进度条；900像素及以下转为卡片；620像素及以下改为单列布局。
页面和弹框最小字号为12像素，项目名称和金额不会被压成逐字竖排。
