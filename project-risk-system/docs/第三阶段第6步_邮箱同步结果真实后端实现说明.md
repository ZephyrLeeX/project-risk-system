# 第三阶段第6步：邮箱同步结果真实后端实现说明

## 1. 实现范围

本步骤以 `ui-prototype/11-mail-sync-results.html` 为唯一功能和界面基准，把原静态演示数据替换为真实数据库、IMAP、附件解析、项目匹配和 AI 风险提取链路。原型中的功能模块未删减：

- 最近一次同步批次及五类统计卡片。
- 邮件明细、同步批次两个页签。
- 邮件主题、发件人、项目、状态和批次筛选。
- 失败邮件提醒、详情和重新处理。
- 邮件摘要、关键要点、项目匹配、风险线索、附件和处理轨迹。
- 风险线索调整、忽略、确认发布和关联风险入口。
- 同步进度、空状态、未配置状态、错误状态和分页。

正式入口：`http://localhost:5173/mail-sync-results`

## 2. 数据结构与迁移

迁移：`apps/api/prisma/migrations/20260803000400_mail_sync_results/migration.sql`

新增或扩展：

- `mail_sync_batches`：增加业务批次号、重试来源和目标失败邮件。
- `mail_messages`：记录 Message-ID、IMAP UID、处理状态、安全摘要、关键要点、附件元数据和处理轨迹。
- `mail_message_project_matches`：记录项目匹配方式、置信度和命中文本。
- `mail_risk_candidates`：记录 AI 生成但尚未发布的风险候选、人工复核结果及确认后的风险 ID。

数据库使用 `(mailbox_config_id, imap_uid)` 作为强制唯一约束；Message-ID 用于跨批次重复判断，重复邮件仍可形成“已跳过”处理记录，不会再次调用 AI 或重复写入风险。

## 3. 增量同步链路

1. 读取风险管理员本人已启用的邮箱配置和解密后的授权码。
2. 使用只读 IMAP 连接打开配置文件夹。
3. 首次按配置周数搜索，后续从已成功提交的 UID 游标之后增量搜索。
4. 每批最多处理 50 封；同一邮箱同时只允许一个排队或运行批次。
5. 完成 UID/Message-ID 去重和主题、发件人规则判断。
6. 对正文做安全清洗；附件仅解析 TXT、DOCX、PDF、XLSX，单个附件最大 10MB，整封邮件最大 25MB。
7. 按项目标准名称和别名进行真实匹配并保存置信度。
8. 调用后台已启用且健康的 AI Provider 执行结构化风险提取；没有可用 Provider 时明确失败，不生成假风险。
9. 仅在整批没有失败邮件时推进邮箱 UID 游标，避免失败邮件被永久越过。

## 4. 人工复核与风险发布

- AI 结果先保存为 `PENDING` 候选，不直接进入风险看板。
- 风险管理员可调整项目、分类、等级、描述、证据和建议措施。
- “忽略线索”将候选改为 `IGNORED` 并保留审计记录。
- “确认并发布”在一个数据库事务中创建正式 `Risk`、风险时间线、关联待办和确认关系。
- 正式风险来源为 `MAIL_AI`，使用候选 ID 生成稳定去重指纹。
- 所有候选查询都通过当前会话用户的邮箱配置做本人隔离，不能读取或处理其他人的邮件。

## 5. API

- `GET /api/mailbox/sync-summary`
- `GET /api/mailbox/review-options`
- `GET /api/mailbox/messages`
- `GET /api/mailbox/messages/:id`
- `POST /api/mailbox/messages/:id/retry`
- `GET /api/mailbox/sync-batches`
- `GET /api/mailbox/sync-batches/:id`
- `PATCH /api/mailbox/risk-candidates/:id`
- `POST /api/mailbox/risk-candidates/:id/ignore`
- `POST /api/mailbox/risk-candidates/:id/confirm`

页面沿用第 10 页的 `POST /api/mailbox/me/sync` 创建手动同步任务，并轮询同步汇总直到任务成功、部分失败或失败。

## 6. 权限与审计

- 页面和查询要求 `mailbox.sync_self`，并在服务端再次限制角色必须为风险管理员。
- 风险候选调整、忽略和确认同时要求 `risk.resolve`。
- 重试、调整、忽略和确认均写入敏感审计记录；审计快照不保存授权码、原始邮件源文件、完整附件或 AI 原始响应。
- AI 调用写入 `ai_call_logs`，仅记录 Provider、模型、耗时、Token、结果和错误摘要，不保存提示词及响应正文。

## 7. 安全边界

- 邮箱正文和附件只作为数据处理，不执行脚本、宏、外部链接或附件中的指令。
- 清洗脚本/样式、外链和控制字符；数据库只保存安全摘要、关键要点与附件元数据。
- 大文件、附件解析失败、IMAP、规则、项目匹配和 AI Provider 异常均保留明确处理状态，禁止静默伪造成功。
- 失败任务可以按原 UID 单封重试，不会错误推进全局游标。
