## 工程组成

- `apps/web`：Vue 3、TypeScript、Vite 前端；
- `apps/api`：NestJS、TypeScript API 服务；
- `packages/contracts`：前后端共享类型、枚举和响应契约；
- `infra`：PostgreSQL 与本地容器编排；
- `storage`：Excel、邮件和备份文件的本地挂载目录；
- `legacy-prototype`：现有静态原型的位置说明。

现有11页视觉基线继续保留在上一级目录的 `ui-prototype`，不得直接作为生产代码或生产数据源。

## 本地准备

1. 执行 `pnpm env:init`，生成权限为 `600` 的本地 `.env` 和随机密钥；
2. 安装依赖：`pnpm install`；
3. 生成 Prisma Client：`pnpm prisma:generate`；
4. 启动 PostgreSQL：`pnpm db:up`；
5. 应用现有迁移：`pnpm --filter @risk-platform/api exec prisma migrate deploy`；
6. 初始化角色权限与管理员：`pnpm prisma:seed`；
7. 启动前后端：`pnpm dev`。

种子脚本会读取 `.env` 中的 `INITIAL_ADMIN_USERNAME` 和
`INITIAL_ADMIN_PASSWORD`。初始密码必须满足复杂度要求，且首次登录后必须修改；
脚本不会在控制台输出密码，也不会在重复执行时覆盖已有管理员密码。
`pnpm env:init` 同样不会覆盖已有 `.env`，也不会在终端输出生成的敏感值。
数据库命令会显式读取项目根目录 `.env`；Compose配置拒绝使用默认数据库密码。

## 当前认证接口

- `POST /api/auth/login`：账号密码登录并写入 HttpOnly 会话 Cookie；
- `GET /api/auth/session`：恢复当前登录会话；
- `POST /api/auth/change-password`：首次登录或主动修改密码，成功后撤销全部会话；
- `POST /api/auth/logout`：撤销当前会话并清除 Cookie。

默认会话有效期为 8 小时；连续失败 5 次后锁定 30 分钟，均可通过环境变量调整。

## 当前后台管理能力

- 用户管理：查询筛选、创建、编辑、启停、解锁、密码重置和操作记录；
- 角色权限：系统角色查看与受约束编辑、自定义角色创建/复制/删除、权限分组配置；
- 项目数据范围：全部项目、本人负责、被授权、本人负责及授权、无项目数据；
- 权限校验：前端路由控制和后端接口守卫同时生效，后端作为最终安全边界；
- 安全处理：初始密码仅返回一次，停用或重置密码会立即撤销用户现有会话；
- 审计留痕：用户、角色和项目范围的关键变更均写入审计日志。

后台管理接口统一使用 `/api/admin` 前缀，主要包括：

- `/users`、`/users/:id/status`、`/users/:id/reset-password`；
- `/users/:id/project-scopes`、`/users/:id/records`；
- `/roles`、`/permissions`；
- `/departments`、`/projects/options`。

对应前端入口为 `/admin/users` 和 `/admin/roles`。未登录用户会被送往登录页，
缺少相应权限的用户会进入无权访问页。

## 项目清单 Excel 导入

系统管理员可通过 `/admin/imports` 上传 `.xlsx` 项目清单。导入采用两阶段流程：

1. 预检：解析“数据回款”“涵谷回款”和“发函-诉讼清单”，展示项目动作、
   补充记录、法务事项的匹配状态、警告和错误；
2. 确认：错误行为零且管理员确认全部警告后，事务性写入项目、部门、补充记录、
   法务事项和批次明细；
3. 回滚：没有后续批次覆盖相关项目时，可恢复更新前快照并删除本批次新增项目。

“涵谷回款”独立保存为补充回款数据。系统会读取隐藏金额列和月度回款，尝试按
项目编码或项目名称精确匹配；未匹配记录保留为待匹配，不创建项目、不改变项目总数。

“发函-诉讼清单”独立保存为法务事项，读取月度回款、回款风险和法务进展，
按项目编码或名称匹配主项目；匹配成功后建立关联，不重复创建项目。
确认导入时，“数据回款”的有效风险等级会生成回款风险记录，
已匹配的“发函-诉讼清单”事项会生成发函诉讼风险记录；批次回滚时风险与项目
一并恢复。

接口统一使用 `/api/imports/project-list` 前缀：

- `POST /preview`：上传并预检 Excel，单文件上限20MB；
- `GET /batches`、`GET /batches/:id`：查询批次历史与逐行结果；
- `POST /batches/:id/confirm`：确认警告后正式入库；
- `POST /batches/:id/rollback`：回滚已导入批次。

## Web 风险看板

登录后的正式首页为 `/`。页面从数据库读取真实项目与风险数据，包含5项指标、
本周重点关注、风险筛选分页和完整详情，并接入部门回款汇总、管理者待办、
应收与回款、风险时间线、已解除风险5个真实业务模块。

主要接口：

- `GET /api/dashboard/summary`；
- `GET /api/dashboard/focus`；
- `GET /api/risks/options`；
- `GET /api/risks`；
- `GET /api/risks/:id`。

所有接口同时执行 `dashboard.view` 权限检查和项目数据范围过滤。
源 Excel 金额为空时返回空值并显示“数据待补充”，不会使用原型演示金额。

## 部门回款汇总

“部门回款汇总”页签已接入真实数据。系统优先采用项目清单完整金额；
项目清单金额不完整时，只使用已由管理员确认关联的“涵谷回款”记录作为补充。
未匹配记录不会计入任何部门。

主要接口：

- `GET /api/dashboard/departments/collections`；
- `GET /api/dashboard/departments/:departmentKey/collections`；
- `GET /api/imports/project-list/projects/options`；
- `POST /api/imports/project-list/supplemental/:id/match`；
- `DELETE /api/imports/project-list/supplemental/:id/match`。

关联和解除操作均校验导入状态、目标项目状态和管理员权限，并写入审计日志。

原始文件默认保存在 `storage/excel/<批次ID>/source.xlsx`，可通过
`IMPORT_STORAGE_DIR` 指定其他存储根目录。中文文件名会按 UTF-8 规范化后记录。

## 管理者待办

“管理者待办”页签已接入真实数据。确认导入项目清单时，每条有效风险自动形成
一条关联待办；同一风险不会重复生成。待办保留风险来源、证据与建议措施，并可按
负责人和处理状态筛选。

主要接口：

- `GET /api/todos`：按数据范围查询待办、汇总和本周日程；
- `GET /api/todos/:id`：查看完整待办及关联风险；
- `PATCH /api/todos/:id`：更新负责人、状态、截止日期和处理说明。

查看接口校验 `dashboard.view` 权限；更新接口额外校验 `risk.resolve` 权限。
所有查询均执行项目数据范围过滤，更新操作写入 `ACTION_ITEM_UPDATED` 审计日志。
批次回滚会同步恢复或删除自动生成的待办。

## 应收与回款

“应收与回款”页签已接入真实风险项目数据，只统计当前存在有效风险、且在当前
用户项目数据范围内的项目。列表支持按项目、风险等级和负责人筛选，展示计划金额、
已回款、剩余待回款、下一笔回款和回款进展；详情保留12个月回款数据和全部有效风险。

金额优先采用项目清单中的完整金额三元组；项目清单金额不完整时，仅使用已确认
关联的补充回款记录。空金额保持为空并展示“待补充”，不会当作0或使用原型演示值。
下一笔回款优先取当月及以后标记为“预计/计划”的月度金额；没有月度金额时仅展示
原始回款进展文本，不虚构金额或日期。

主要接口：

- `GET /api/dashboard/collections`：查询风险项目回款汇总和筛选结果；
- `GET /api/dashboard/collections/:projectId`：查询项目回款、月度计划和关联风险详情。

两个接口均校验 `dashboard.view` 权限并执行项目数据范围过滤。本步骤复用现有
项目、风险和补充回款表，不新增数据库迁移。

## 风险时间线

“风险时间线”页签已接入独立事件数据。项目清单确认导入时自动记录风险首次识别
和风险处理待办生成；后续重新导入会记录风险信息更新、等级变化或风险重启；
待办负责人、截止日期、处理说明和状态变化也会追加事件。事件不会覆盖历史。

主要接口：

- `GET /api/dashboard/timeline`：按关键词、事件类型、风险等级和项目筛选并分页；
- `GET /api/dashboard/timeline/:id`：查看事件、关联风险和关联待办完整详情。

两个接口均校验 `dashboard.view` 权限并执行项目数据范围过滤。批次回滚会同步
清理该批次产生的时间线事件；新建项目删除时，关联事件通过外键级联清理。

## 已解除风险

风险管理员可在风险详情中填写原因并解除风险。解除时，系统在同一事务中更新
风险状态、解除时间、解除人和解除原因；未完成的关联待办同步完成，并追加待办完成、
风险解除两类时间线事件及 `RISK_RESOLVED` 审计。解除原因必须为5至2000个字符。

“已解除风险”页签按当前用户项目数据范围展示历史记录，支持按关键词、原风险等级、
原风险类别和项目负责人筛选，保留风险、项目、解除时间、解除人和完整解除原因。
具备 `risk.resolve` 权限的用户可填写原因重新打开风险；系统会恢复关联待办，
追加处理推进、风险重启事件及 `RISK_REOPENED` 审计。

主要接口：

- `GET /api/risks/resolved`：查询已解除风险并分页；
- `POST /api/risks/:id/resolve`：填写原因并解除风险；
- `POST /api/risks/:id/reopen`：填写原因并重新打开风险；
- `GET /api/risks/:id`：查看有效或已解除风险完整详情。

查询接口校验 `dashboard.view`，状态变更额外校验 `risk.resolve`；所有接口均执行
项目数据范围过滤。状态、待办、时间线和审计在同一数据库事务中更新。

匹配状态、隐藏金额字段、批次统计及项目可选关联。
发函诉讼导入新增迁移 `20260730000200_legal_matter_import`，包括法务事项、

来源、责任人、截止日期、完成信息，以及项目、风险和用户关联。
