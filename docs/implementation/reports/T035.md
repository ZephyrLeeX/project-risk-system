## 实现摘要

- **`infra/docker-compose.yml`**：全栈服务。`x-backend-env` YAML anchor 让 api/worker 共享 DATABASE_URL/CELERY_BROKER_URL/DATA_ENCRYPTION_KEY/IMPORT_STORAGE_DIR；scheduler 显式声明其所需 env（不含 `DATA_ENCRYPTION_KEY`/`IMPORT_STORAGE_DIR`，因不构造 domain service/cipher，ADR 0030 §2）。双网络：`project-risk-backend`（固定子网 `10.30.0.0/24`，trust boundary；proxy 为唯一 host 暴露服务，API 设 `TRUSTED_PROXY_CIDRS=10.30.0.0/24`）+ 既有 `project-risk-network`（`pnpm db:up`/integration 容器，postgres 挂双网）。postgres 保留 `127.0.0.1` host bind，dev/integration 不变。required env 用 `${VAR:?...}` fail-fast。持久 named volumes：`project-risk-postgres-data` + `project-risk-storage`。session key 经 compose `secrets`（只读文件挂载）。
- **`infra/proxy/nginx.conf`**：TLS 1.2/1.3、HSTS/X-Frame-Options/X-Content-Type-Options/Referrer-Policy、`client_max_body_size 50m`。SSE location `~ ^/api/agent/conversations/.+/events$`（`proxy_buffering off`/`proxy_cache off`/`proxy_read_timeout 3600s`/`proxy_send_timeout 3600s`/`chunked_transfer_encoding on`），regex 先于 `/api/` prefix 匹配，故 SSE 不被 buffering/timeout 破坏（ADR 0016）。`/api/` → `api:3000`，`/` → `web:80`。
- **`infra/proxy/frontend.conf`**：web image 的 SPA 静态服务（try_files fallback、`/assets/` immutable cache）。
- **`apps/api-python/Dockerfile` + `.dockerignore`**：`python:3.12-slim` + uv 多层构建，非 root `appuser`（uid 1001），CMD `uvicorn risk_platform.main:app`。`apps/web/Dockerfile`：`node:22-bookworm-slim` → `nginx:1.27-alpine` 两阶段（`pnpm install --frozen-lockfile --filter @risk-platform/web...`，先构建 contracts 再构建 SPA；runtime 仅 nginx + 静态产物，无 Node/NestJS/Prisma runtime）。pnpm 经 `npm install -g pnpm@11.9.0` 获取（corepack 在构建容器内 registry fetch 不稳定）。根 `.dockerignore` 排除 `apps/api/**`（NestJS）等，使 web 构建上下文不含遗留栈。
- **`infra/env.example` / `infra/README.md` / `infra/scripts/init-secrets.sh`**：生产 env 模板、部署 runbook（services/networking/trust/secrets/init/operate/SSE/single-active scheduler/out-of-scope）、test secret/cert bootstrap（openssl 生成 session key + 自签 TLS 证书，均 gitignored）。
- **`uvicorn[standard]` 依赖**（用户批准）：production image 需 ASGI server，此前 `pyproject.toml` 未声明 uvicorn（仅 TestClient 测试）。已加 `"uvicorn[standard]>=0.34,<1"` 并 `uv lock`，OpenAPI authority 不变。

### scheduler 接线（T035 仅 deployment wiring）

scheduler service 复用 `risk-platform-api:0.1.0` image，`command` 调用 T046 entrypoint `risk_platform.scheduler:main`。因 `scheduler.py` 无 `if __name__ == "__main__"` guard，`python -m risk_platform.scheduler` 会 import 后 exit 0 而不启动循环，故 Compose `command` 显式调用 `main()`：`python -c "from risk_platform.scheduler import main; main()"`。此为调用既有 entrypoint，未新增 scheduler 逻辑、未修改 `scheduler.py`。scheduler wiring 含 command/entrypoint、cadence env（4 个 `SCHEDULER_*_INTERVAL_SECONDS`）、DB/Redis 连接 env、`:9191` liveness healthcheck、`restart: unless-stopped`、`stop_grace_period: 60s`。

### Non-blocking observations

- **README scheduler command 描述**：原 README 以 `python -m risk_platform.scheduler` 描述，与实际 compose `command`（显式调用 `main()`）不一致；已修正并补充说明（requirement #12 docs 与实际一致）。已在本 checkpoint 修复。
- **scheduler fail-fast 路径连接警告**：lock 已被持有时 `Scheduler.run()` 直接 `return 1` 不调用 `release()`（唯一关闭 `lock_conn` 的路径），可能触发 SQLAlchemy "non-checked-in connection" warning。该代码位于 frozen `scheduler.py`（T046 write-set），非 T035 范围；进程即将退出且 `async_main` finally 调 `dispose_database_engine`，session-level lock 由 PostgreSQL 在连接/进程终止时自动释放，仅 cosmetic、无功能影响。归属 T046 follow-up，非 T035 blocker。
