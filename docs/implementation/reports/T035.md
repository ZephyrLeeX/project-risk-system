## 结论

T035 的 Objective 明确要求定义包含 **scheduler** 在内的单机 Compose（"proxy, Python API, worker, scheduler, PostgreSQL and Redis"）。Lean Execution Mode 加载 T035 引用的 ADR（0001/0003/0006/0009/0010/0014/0016）、设计 §§4/7/9、Python process contracts（`main:app`、`worker`、`composition`、`celery_app`）与既有 `infra/docker-compose.yml` 后确认：**批准的设计中不存在 scheduler 组件，也没有任何已批准的周期性触发机制**，而代码中需要周期性/提交后驱动的可靠性入口均未接线。T035 无法在其 write-set（Compose/proxy/Dockerfile/env/docs）内 materialize 一个 scheduler，除非做出未经批准的架构决策或跨越 frozen write-set。按 ORCHESTRATOR 协议与 T027/T029/T030/T033 的 stop 先例，本轮记录 `DESIGN_GAP` 并停止，不自行补决策、不实施、不创建 code checkpoint。

## DESIGN_GAP 证据

### 1. Objective 要求一个 scheduler 组件，但批准的架构中没有它

- 设计 §4 架构图包含 `Web → Proxy → API → PostgreSQL/Redis → Worker → PostgreSQL/IMAP/AI`、`API/Worker → Files`、`Backup → PG/Files`，**没有 scheduler/beat 框**。
- ADR 0006（模块化 FastAPI 单体 + Celery Worker）只定义 Worker 与 Redis broker，**未提及 beat/scheduler/周期触发进程**。
- T035 task Objective 与 Required deliverables 列出 "scheduler"，但其机制、cadence、进程类型、single-active 语义在 ADR/设计中均无批准决策。

### 2. 需要周期性驱动的可靠性入口均无 production caller

Lean Execution Mode 加载 Python process contracts 后，逐项核验：

| 入口 | 来源契约 | 用途 | production caller |
|---|---|---|---|
| `publish_outbox` | ADR 0018 §"Transactional outbox 与投递"（"outbox publisher 在数据库 transaction 提交后向 Celery 发布"） | 将 `task_outbox` 行发布到 Celery，驱动 at-least-once dispatch | **无**（仅 `dispatcher.py` 定义 + `__all__`；仅 tests 调用） |
| `reconcile` | ADR 0018 §"Reconciliation"（lost dispatch / retry due / expired lease） | 周期性恢复丢失投递、到期重试、过期 lease | **无**（`reliability/core.py:reconcile` 注释自述 "periodic reconciliation"，但无 production 调用方） |
| `schedule_enabled_syncs` | T024（scheduled mailbox sync，`autoSyncIntervalMinutes`/`nextSyncAt`，`_INTERVAL_MINUTES=30`） | 为到期 mailbox 创建 SCHEDULED 同步批次 | **无**（仅 `mailbox/sync.py` 定义 + `__all__`；无 production 调用方） |

核验命令（均确认无 production 调用方）：

```
grep -rn "publish_outbox"        apps/api-python/src   # 仅 def + __all__
grep -rn "reconcile("            apps/api-python/src   # 无非定义调用
grep -rn "schedule_enabled_syncs(" apps/api-python/src # 无非定义调用
find apps/api-python/src -iname '*beat*' -o -iname '*schedul*'   # 无模块
grep -n "beat" reliability/celery_app.py                # NO beat in celery_app
```

- `celery_app.py`（frozen T040 write-set）**无 `beat_schedule`**；不存在 `*scheduler*`/`*beat*` entrypoint 模块。
- `enqueue_task`（imports/mailbox/agent/weekly/retention services 调用）在 caller 事务内创建 `DurableTask` + `TaskOutbox` 行，但 production 路径从不调用 `publish_outbox`，亦无 `send_task` 直发——**即生产环境下任务被持久化但从不投递到 Celery**（tests 通过手动 `publish_outbox`/`execute_message`/`start_worker` 驱动）。

### 3. materialize scheduler 超出 T035 write-set 且需未经批准的决策

T035 write-set（task 明示）：Production Compose file(s)、`infra/proxy/**`、Python Docker files、env examples、deployment docs；**不含 application entrypoint，不含 `celery_app.py`**。deploy 一个 scheduler 至少需要其一：

- **新增 application entrypoint**（如 `risk_platform/scheduler.py`，asyncio 循环周期调用 `reconcile`/`schedule_enabled_syncs`/`publish_outbox`）——属 `risk_platform/` 应用代码，不在 T035 write-set；且需构造 production session/依赖，触及 T040 独占的 composition 边界；并需决定 cadence、single-active、错误处理——均无批准决策。
- **在 `celery_app.py` 增加 `beat_schedule`** + beat task target wrapper——`celery_app.py` 属 frozen T040 write-set，修改即 `DESIGN_DEVIATION`；且 beat target wrapper 为新应用代码；cadence（sync 30 min、reconciliation interval）为未经批准的运维/可靠性数值决策（与 DG-05 deferred reliability thresholds 相邻）。

任一选择都违反 "不自行补决策" 与 frozen write-set 纪律，构成 `DESIGN_GAP`/`DESIGN_DEVIATION`，故停止。

## 相关发现（非 T035 write-set，记录供后续 owner）

- **ADR 0018 outbox publisher 未接线**：`publish_outbox` 按 ADR 0018 应"在 transaction 提交后向 Celery 发布"（inline post-commit），但 production 请求路径（imports/mailbox/agent/weekly/retention services 的 `enqueue_task` 之后）从不调用它。这是 T008（reliability）/各 feature service frozen write-set 内的实现缺口，不在 T035 write-set；但它意味着即便补齐 scheduler，正常 dispatch 路径在生产环境仍非功能，直到该 owner 接线 post-commit publish。本轮仅记录，不修改 frozen write-set。
- **Reconciler 触发机制未定义**：ADR 0018 §"Reconciliation" 要求 Reconciler，但未规定触发方式（周期进程 / worker 启动 / inline）。设计 §8 "Worker 重启后根据数据库状态恢复遗漏任务" 暗示 startup 恢复，但 `reconcile()` 注释自述 "periodic reconciliation"，二者未由任何 ADR 统一。
