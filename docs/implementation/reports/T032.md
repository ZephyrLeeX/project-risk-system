## 实施摘要

T032 目标是将 reviewed FastAPI OpenAPI 冻结为唯一契约权威，并复现生成前端 TypeScript 类型。本轮按 Lean Execution Mode 完成了 authority/generation 基础设施与 compatibility 检查工具；compatibility 检查在运行中暴露出 FastAPI 后端缺失前端实际消费的 `/api` 端点，触发 T032 stop condition（"A breaking diff lacks approval"），故停止、记录 `DESIGN_GAP`，未创建 code checkpoint，未进入 Independent Review 通过路径。

## DESIGN_GAP — 兼容性差异未获批准（stop）

运行 `openapi-compat.mjs` 后，compatibility check 报告 7 个 **breaking** 差异：前端实际消费、且 NestJS reference 提供的 `/api` 端点，在 FastAPI OpenAPI authority 中不存在。

| # | 前端调用 | 来源 | NestJS reference | FastAPI 状态 |
|---|---|---|---|---|
| 1 | `GET /api/admin/projects/options` | `apps/web/src/api/admin.ts:153`（`adminApi.projectsOptions`，用户分配项目选择器） | `apps/api/src/admin/admin.controller.ts:232 @Get("projects/options")`（`admin.scope.manage`） | 缺失（仅有 `/admin/system-config/project-options`、`/imports/projects/options`、`/risks/options`） |
| 2 | `GET /api/mailbox/sync-summary` | `mailbox.ts:57`（`MailSyncResultsView.vue:124`） | `mail-sync-results.controller.ts:45` | 缺失 |
| 3 | `GET /api/mailbox/review-options` | `mailbox.ts:61`（`MailSyncResultsView.vue:229`） | `mail-sync-results.controller.ts:50` | 缺失 |
| 4 | `GET /api/mailbox/messages` | `mailbox.ts:70`（`MailSyncResultsView.vue:133`） | `mail-sync-results.controller.ts:55` | 缺失 |
| 5 | `GET /api/mailbox/messages/{id}` | `mailbox.ts:74`（`MailSyncResultsView.vue:190`） | `mail-sync-results.controller.ts:60` | 缺失 |
| 6 | `POST /api/mailbox/messages/{id}/retry` | `mailbox.ts:78`（`MailSyncResultsView.vue:220`） | `mail-sync-results.controller.ts:65` | 缺失 |
| 7 | `GET /api/mailbox/sync-batches` | `mailbox.ts:82`（`MailSyncResultsView.vue:152`） | `mail-sync-results.controller.ts:70`（含 `sync-batches/{id}`） | 缺失 |

`MailSyncResultsView` 已在 `apps/web/src/router/index.ts:116` 注册路由并被上述端点驱动，属活跃前端功能。FastAPI mailbox 模块（T023–T026）仅迁移了 `/mailbox/me*`（配置/连接测试/同步触发）与 `/mailbox/risk-candidates/*`（候选复核/确认/忽略），未迁移 `mail-sync-results.controller.ts` 的浏览面（sync-summary / review-options / messages / messages/{id} / retry / sync-batches）。

### 性质判定

- 这不是 T032 引入的 regression，而是**既存的迁移覆盖缺口**：FastAPI 后端（OpenAPI authority）尚未实现既有 `/api` 端点，而 Task Graph 中无任何 Task 拥有这些端点的迁移（T023 配置/连接测试、T024 UID 同步、T025 解析、T026 候选提取/复核；均不含 sync-results 浏览端点；`/admin/projects/options` 同样无 owner）。
- ADR 0001 要求 FastAPI 兼容现有 `/api` 路径/字段/错误/Cookie/分页；ADR 0011 以现有 TypeScript 契约与前端行为为兼容基准。冻结一个缺失活跃前端消费端点的 OpenAPI 为"唯一权威"，会将与既有 `/api` surface 的不一致固化为权威，违反 backward-compat 基准。
- T034（"Cut dashboard, weekly reports, mailbox and Agent UI to real Python APIs"）依赖 mailbox 浏览端点存在；当前缺失使其无法完成 mailbox UI cutover。
- 因此这是 `DESIGN_GAP`：approved design/task-graph 缺少将这些端点迁移到 FastAPI 的 owner/决策；在解决前，T032 无法满足 acceptance "compatibility diff approved" 与 stop condition "A breaking diff lacks approval"。

## DESIGN_GAP 解决 — ownership 映射（metadata checkpoint，未实现 production code）

经 Orchestrator 决策，采用**新增 remediation Task**而非扩展已完成 Task 的方案（已完成 Task 的 write-set 已冻结于 `REVIEW_PASSED`，重开将违反单工作单元/冻结写集不变量并触发不必要的重审）。7 个缺失操作分属两个不相交模块写集，按项目 Wave/并行惯例拆为两个 READY Task：

### T043 — Mailbox sync-results browse/retry surface（owns 6 个前端消费操作 + 1 同面 detail）

- **范围：** `GET /mailbox/sync-summary`、`GET /mailbox/review-options`、`GET /mailbox/messages`、`GET /mailbox/messages/{id}`、`POST /mailbox/messages/{id}/retry`、`GET /mailbox/sync-batches`，以及同控制器同写面的 `GET /mailbox/sync-batches/{id}`（非前端 live-consumed，但属同一浏览面，未迁移将构成新覆盖缺口）。
- **契约：** 复用既有 `@risk-platform/contracts` 类型（`MailSyncSummary`、`MailRiskReviewOptions`、`MailMessageListResponse`、`MailMessageDetail`、`MailSyncBatchItem`、`MailSyncBatchDetail`、`PaginatedResponse<MailSyncBatchItem>`）；response/field/分页/error envelope/Cookie 遵循 ADR 0001 backward-compat 基准。
- **permission/scope：** 类级 `mailbox.sync_self`；所有操作 scope 至调用者自身 `mailboxConfigId`；`sync-summary` 额外要求 `RISK_ADMIN` 角色（NestJS `ensureRiskAdmin`）；`retry` 要求消息 `FAILED` 状态、拒绝并发 `QUEUED`/`RUNNING` 批次，经 processor 创建审计后的新 sync batch，并遵循 ADR 0022 handoff/terminal-state。
- **依赖：** T006、T010、T023、T024、T025、T026（均 `REVIEW_PASSED`）。
- **写集：** `apps/api-python/src/risk_platform/mailbox/`（新增 sync-results router/service，与 T023–T026 既有文件 disjoint）。无新 ADR。
- **状态：** `READY`。

### T044 — Admin project-options selector（owns 1 个操作）

- **范围：** `GET /admin/projects/options` → `ProjectOption[]`（用户项目分配选择器）。
- **契约：** 复用既有 `ProjectOption` 类型；ADR 0001 兼容基准。
- **permission/scope：** `admin.scope.manage`。
- **依赖：** T005、T010（均 `REVIEW_PASSED`）。
- **写集：** `apps/api-python/src/risk_platform/admin/options/`（对 T012 既有 options 模块**仅追加** `projects/options` 路由与 service 方法，不修改既有 `departments` 路由；T012 冻结面保持 additive-only，不触发 T012 重审）。
- **状态：** `READY`。
