## 结论

T046 实现了 ADR 0030 批准的生产调度器拓扑：一个**独立的 scheduler 进程**（不采用 Celery Beat），在专用长连接上获取 **PostgreSQL session-level advisory lock** 保证 single-active，周期驱动三个已存在 service entry point —— outbox drain（`publish_outbox`，默认 5s）、reconciliation（`reconcile`，默认 30s）、scheduled mailbox sync（`schedule_enabled_syncs`，默认 5min）。scheduler 是 production 路径**唯一的 publisher**：请求路径仅写 PostgreSQL（`enqueue_task` 写 `DurableTask`+`TaskOutbox`，不碰 broker），无 DB/Celery dual-write，PostgreSQL 仍为唯一 authority，Redis/Celery 仅为 delivery/execution transport（ADR 0018/0030）。

实现为单一新模块 `apps/api-python/src/risk_platform/scheduler.py`（进程入口、advisory-lock 循环、tick 编排、per-function cadence gating、per-tick/per-function failure isolation、liveness 探针、startup retry、SIGTERM graceful shutdown）。**只读复用**五个 public 入口（`risk_platform.db` 的 `database_url`/`create_database_engine`/`create_session_factory`/`dispose_database_engine`/`transaction`、`risk_platform.reliability.celery_app.celery_app`、`risk_platform.reliability.dispatcher.publish_outbox`、`risk_platform.reliability.core.reconcile`、`risk_platform.mailbox.sync.schedule_enabled_syncs`），**未编辑** `composition.py`/`celery_app.py`/`worker.py`/`main.py` 或三个 driven 函数。scheduler 不注册 Celery executor、不配置 beat、不构造 domain service、不写业务 audit（ADR 0017），日志仅含操作 metadata，不含 secret/mail content/payload（ADR 0014/0007）。Independent Review `REVIEW_PASSED`，无 blocking finding。

## 设计要点（ADR 0030 落地）

- **single-active fence**：`pg_try_advisory_lock(:key)`，固定单 bigint key `0x7269736B5F736368`（'risk_sch'，8 ASCII bytes，符合 signed int64）。获取成功进入 tick 循环；获取失败（`False`，lock 已被持有）→ 以非零状态 exit 1（fail-fast，不运行第二个 active scheduler）。session-level lock 随该连接存活，进程崩溃/连接关闭时自动释放，无需额外 fencing token；driven 函数本身幂等构成 defense-in-depth。
- **tick 编排**：每 tick 先 `lock_ping`（`SELECT 1` + commit）确认 lock 连接存活——失败则标记不健康并 exit 1 触发重启；随后逐 action 按各自间隔独立判断是否到期。三动作各自 `try/except`：一个动作抛错被记日志后隔离，**不阻塞其他动作、不中断循环**；失败动作的 `_last_run` 不前进，下个 tick 保持到期重试（per-tick/per-function isolation）。
- **cadence**（operational defaults，非 SLO；DG-05 out of scope）：outbox drain 5s、reconcile 30s、mailbox sync 300s，poll 1s。经 `SCHEDULER_OUTBOX_DRAIN_INTERVAL_SECONDS`/`SCHEDULER_RECONCILE_INTERVAL_SECONDS`/`SCHEDULER_MAILBOX_SYNC_INTERVAL_SECONDS`/`SCHEDULER_POLL_INTERVAL_SECONDS` env 调整；非正/非数字 → `SchedulerConfigurationError` exit 2 fail-fast。
- **outbox at-least-once**：`make_drain_outbox` 把 `publish_outbox` 包在 caller-owned `transaction()` 内；`publish_outbox` 逐行 `send_task` 成功后才置 `publishedAt`，broker publish 抛错则事务回滚、该行保持未发布、下个 drain 重试（ADR 0018）。
- **liveness**：`LivenessState`（thread-safe `threading.Lock`）在 async tick loop 与 stdlib HTTP 探针线程间共享。`/healthz` 仅当 (a) 持有 advisory lock 且 (b) 最近一次成功 tick 在窗口内（默认 ≤ 2× outbox drain 间隔）时返回 200，否则 503。探针用 stdlib `ThreadingHTTPServer`，无额外依赖（ADR 0030 §7）。
- **startup/shutdown**：startup 连接 PostgreSQL（`connect_with_retry` 有界重试，仅 DBAPIError 重试，超过则 exit 1 触发 restart）→ 获取 advisory lock（`acquire_lock_with_retry`，`False` 立即返回不重试）→ 进入 tick 循环。SIGTERM/SIGINT 设置 `stop` event，`run()` 在当前 tick 完成后退出（`_interruptible_sleep` 可被唤醒），`finally` 释放 lock + 关闭连接；config error（`SchedulerConfigurationError`/`DatabaseConfigurationError`）→ exit 2。
- **可测性**：`Scheduler` 的依赖（acquire/release/lock_ping/actions/clock/sleep）全部注入，cadence/isolation/shutdown/liveness 无需数据库即可 unit-testable；production wiring 在 `async_main`/`main`。

- **[minor, non-blocking] `_interruptible_sleep` shield 模式**：`asyncio.shield(stop.wait())` 超时后留下挂起 coroutine（loop 关闭时清理），`asyncio.wait([stop.wait()], timeout=...)` 更简洁。无害。
- **[minor, non-blocking] `_last_run` 取 action 后 clock**：interval 从完成时计而非 tick 开始，差为 action 执行耗时，相对 5s+ 间隔可忽略。
- **[minor, non-blocking] acquire 后 commit 边界**：commit 失败后重试可能用断连，极罕见且 fail-fast restart 可接受。
