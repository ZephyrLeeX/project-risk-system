## ADR 0025 resolution

ADR 0025 已批准 `MAIL_PROVIDER_DERIVED_CONTENT_V1`。T026 每次执行或 retry 均按 ADR 0022
identity 重抓并按 ADR 0024 重新解析，只在 Worker 内存构造受限、过滤的 `analysis_text`。Provider
不得接收 raw source、完整正文/附件、subject、sender、任何 RFC 822 header、附件文件名或内部
identity；允许文本、字段、`12,000` 字符总上限、脱敏、retry、call log 和 audit 边界以 ADR 0025
为准。该设计没有从 NestJS 历史行为推导。

ADR 0025 的 raw-content/design gap 已解决，但本次 Implement 开始前发现以下独立缺口。

## DG-12：Provider risk-category selection/mapping

T026 的候选必须严格验证并持久化本地 `categoryId`，而 ADR 0025 将 Provider 输入明确限制为
`schema_version`、日期、opaque `project_options`、派生文本及纯数值统计；它没有批准任何风险分类
选项、taxonomy 或 Provider 返回分类选择映射。让 Provider 猜测本地分类、向 Provider 发送未批准的
分类字段，或采用 NestJS legacy 的 categories payload 都会违反已批准设计。

因此在任何代码、migration、API 或测试变更前停止。需要新的 ADR/design addendum 明确 Provider 可见
的分类选择/映射边界，T026 才能恢复为 `READY`。
