## ADR 0025 resolution

ADR 0025 已批准 `MAIL_PROVIDER_DERIVED_CONTENT_V1`。T026 每次执行或 retry 均按 ADR 0022
identity 重抓并按 ADR 0024 重新解析，只在 Worker 内存构造受限、过滤的 `analysis_text`。Provider
不得接收 raw source、完整正文/附件、subject、sender、任何 RFC 822 header、附件文件名或内部
identity；允许文本、字段、`12,000` 字符总上限、脱敏、retry、call log 和 audit 边界以 ADR 0025
为准。该设计没有从 NestJS 历史行为推导。

ADR 0025 的 raw-content/design gap 已解决，但本次 Implement 开始前发现以下独立缺口。

## DG-12 resolution：Provider risk-category selection/mapping

ADR 0026 已批准 `MAIL_PROVIDER_DERIVED_CONTENT_V2` 与 `RISK_CATEGORY_OPTIONS_V1`。每次调用仅投射
当前活动类别为 `C1`、`C2`……及其受限语义字段；Provider 必须返回恰好一个 opaque
`category_option_id`，T026 才可确定性地映射到本地 `categoryId`。Provider 不可自由生成分类，也没有
默认、关键词、历史或 NestJS legacy fallback。未知、缺失或歧义分类会 fail closed 为
`PERMANENT_FAILURE` `PROVIDER_INVALID_OUTPUT`；映射在持久化前过期才通过 ADR 0018 重新构建 V2
payload 后 retry。

因此 DG-12 已解决，T026 恢复为 `READY`。本工作单元仍未开始代码、migration、API、tests、Independent
Review 或 PostgreSQL validation。
