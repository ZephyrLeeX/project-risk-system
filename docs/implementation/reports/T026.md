## ADR 0025 resolution

ADR 0025 已批准 `MAIL_PROVIDER_DERIVED_CONTENT_V1`。T026 每次执行或 retry 均按 ADR 0022
identity 重抓并按 ADR 0024 重新解析，只在 Worker 内存构造受限、过滤的 `analysis_text`。Provider
不得接收 raw source、完整正文/附件、subject、sender、任何 RFC 822 header、附件文件名或内部
identity；允许文本、字段、`12,000` 字符总上限、脱敏、retry、call log 和 audit 边界以 ADR 0025
为准。该设计没有从 NestJS 历史行为推导。

ADR 0025 的 raw-content/design gap 已解决，但本次 Implement 开始前发现以下独立缺口。

## DG-12 resolution：Provider risk-category selection/mapping

ADR 0026 已批准 `MAIL_PROVIDER_DERIVED_CONTENT_V2` 与 `RISK_CATEGORY_OPTIONS_V1`。每次调用仅投射
当前活动类别为 `C1`、`C2`……及其受限语义字段；Provider 必须返回恰好一个 opaque
`category_option_id`，T026 才可确定性地映射到本地 `categoryId`。Provider 不可自由生成分类，也没有
默认、关键词、历史或 NestJS legacy fallback。未知、缺失或歧义分类会 fail closed 为
`PERMANENT_FAILURE` `PROVIDER_INVALID_OUTPUT`；映射在持久化前过期才通过 ADR 0018 重新构建 V2
payload 后 retry。

因此 DG-12 已解决，T026 具备实施依据。本报告以下 remediation 状态以当前 working tree 为准。

## 2026-08-12 Celery worker isolation remediation

- PostgreSQL 16 与 Redis broker 可用。每个验收例均创建随机 `t026_*` schema，经 Alembic 升级，并在
  worker handler 中以 `SELECT current_schema()` 断言 worker 使用同一测试 schema；默认/生产 schema 未被使用。
- 发现并修复真实 worker 隔离 defect：`register_executor()` 的同名 Celery task 默认 shared registration 会使
  后续测试 app 复用先前 executor closure，连接已删除 schema。注册现为 `shared=False, lazy=False`，使每个
  Celery app 保有自己的 executor/handler/factory；不改变 T026 业务语义。
- `tests/mailbox/test_extraction.py` 通过 transactional outbox 的 `publish_outbox` 发送 Redis broker message，
  由 `start_worker(pool="solo")` 实际消费；没有以 `execute_message()` 直调替代 worker 证据。该 worker handler
  只注册 `MAIL_AI_REVIEW_PUBLISH`，绑定本例 fake Provider/extractor。
- T025 parser 的 signal timeout 在 embedded worker thread 不可用，故 real-worker T026 tests 在 extraction
  边界替换 `parse_mail` 为受控解析结果；source refetch、Provider/review、durable task 和数据库写入仍在真实 worker
  内执行。这不改变 T025 或 T026 production 语义。
- 验收命令：`TEST_DATABASE_URL=postgresql+psycopg://postgres@127.0.0.1:5432/postgres CELERY_BROKER_URL=redis://127.0.0.1:6379/0 mise exec python@3.12 uv@0.12.3 -- uv run --frozen pytest -q tests/mailbox/test_extraction.py`，结果 `16 passed`。覆盖 success / unavailable / timeout / invalid-output、重复 delivery、duplicate confirm、rollback、scope，以及 adjust / ignore / confirm 与 metadata-only audit 的事务原子性。
- Validation：`ruff check .`、`mypy .`、focused pytest、`uv lock --check` 与 `git diff --check` 均为 `PASS`。
