## Implementation

- 新增 `AiProviderAccount`、`AiModelConfig` 与 metadata-only `AiProviderV2CallLog`。Account 1:N Model；key 只以 `SecretCipher` envelope 和后四位保存；Account/Model health 分离。
- 新增 Alembic head `20260817_0010`，包含 Provider/health enum、FK、Account+Model 唯一约束、稳定候选索引及“同 Account 最多一个 enabled default model”的 PostgreSQL partial unique index。旧 `ai_provider_configs` 与旧 call log 未 backfill、未 dual-write、未删除。
- 新增厂商无关 `AiProviderAdapter`、messages/tools/tool-call/usage/finish/error DTO，以及唯一 production `DeepSeekOfficialAdapter`。官方 origin 固定为 `https://api.deepseek.com`，只访问 `GET /models` 与 `POST /chat/completions`；socket 固定到 outbound guard revalidated IP 并保留官方 Host/SNI/证书校验名，禁用 redirect，限制 request 64 KiB、response 128 KiB。
- 新增 immutable `tuple[ProviderCandidate, ...]` 候选快照，排序为 default DESC → priority ASC → id ASC；过滤 disabled、Account `CREDENTIAL_ERROR`、Model `CONFIG_ERROR`。
- 单模型最多 3 attempts，指数退避+jitter，解析并将 `Retry-After` 限制为 10 秒；network/timeout/408/429/5xx retry 后 failover，404 直接 failover，401/403/其他 4xx/schema/protocol 不 failover。404 只污染 Model health，401/403/credential 只污染 Account health，瞬时错误不永久污染 health。
- 新增 additive `/api/admin/ai-provider-v2/accounts/**` 后端 surface：Account CRUD/status/key rotation/test/model discovery 与 Model CRUD/status/default/test；全部使用 `admin.ai.manage`、标准 `ApiResponse`、typed audit。响应/OpenAPI 不暴露 key/envelope/Authorization/raw body。
- composition/main 仅组装并注册 V2 adapter/service/router；Task 2 Agent Core 尚未消费该 runtime。
- OpenAPI authority 同步到 104 paths / 260 schemas；旧 `/api/admin/ai-services/**` 保持存在，contracts 与现有 Vue frontend typecheck/build 通过。
- 修正两个既有 regression fixtures：mail fake provider 补齐上一版已存在的 `protocol` 参数；composition service graph 纳入新 V2 service；同时收紧既有 Agent provider tests 的 `JSONValue` 类型，不改变生产行为。

## Independent Review

独立 Reviewer 初审结论 `REVIEW_FAILED`，发现四项：已验证 IP 未绑定实际 socket、失败的 Account test health mutation 漏 audit、缺少真实 fake HTTPS wire test、token usage schema 接受非整数。全部已修复：

- 新增 IP-pinned `HTTPSConnection`，socket 连接使用 revalidated address，HTTP Host/TLS SNI/证书校验仍使用原官方 hostname。
- models discovery 失败路径在写 call log/health 后写 `AI_PROVIDER_V2_MODELS_DISCOVERY_FAILED` audit，并新增 PostgreSQL 断言。
- 新增自签名 TLS fake DeepSeek server，通过不可解析 hostname + validated loopback address 实际覆盖 TLS、Host/SNI、Authorization、redirect rejection、`/models` 与 `/chat/completions` wire contract，客观证明不会发生第三次 DNS 解析。
- usage 只接受 JSON integer 且拒绝 float/string/bool，新增参数化负向测试。

第一轮修复后 Reviewer 确认上述四项均已关闭，但复核又发现两个 P2：`Retry-After` header lookup 错误依赖大小写，以及 Account test 把资源不存在的 `404 NOT_FOUND` 转成 `200 success=false`。两项也已修复：

- `Retry-After` 现在按 HTTP 语义大小写无关读取，并新增 lowercase header 回归测试。
- `test_account()` 只把 Provider transport 的 502 typed failure 转为连接测试结果，其他 `ApiError` 原样传播；新增真实 ASGI HTTP-level missing-account 404/error-shape 测试。

第二轮修复后 focused suite `80 passed`，Ruff/mypy 全量再次 PASS。同一独立 Reviewer 第三轮最终复核确认历次 6 项 findings 全部关闭，未发现新 blocker；结论：`REVIEW_PASSED`。
