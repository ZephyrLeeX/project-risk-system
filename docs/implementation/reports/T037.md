## 实现摘要

套件位于 `apps/api-python/tests/acceptance/`，仅含新文件，未编辑任何 feature-module source/test。

- **`conftest.py`** — 验收 harness。每个测试模块独立 PostgreSQL 16 schema（`t037_<uuid>`，`CREATE SCHEMA` + Alembic `command.upgrade(config, "head")` 经 `search_path`），seed 批准的 reference data（4 角色 / 15 权限 / 5 部门 / 风险类别·等级）+ 每默认角色一名真实 argon2 密码哈希用户 + 三项目三风险。组装完整 production app：`build_services(factory, settings, cipher, import_root, ...)` + `create_app(settings, AppComposition(routers=ALL_ROUTERS, lifespan=...))`，全部 17 真实 router。`identity_for(role, scope=...)` 经 `current_identity` dependency override 注入身份以驱动任意角色/范围；`identity=None` 时走真实 cookie/session 路径（CSRF/Cookie 契约）。`build_app(production=True)` 选择 production 环境使 cookie `Secure` 与完整 origin 校验与部署一致。**NullPool**：每个 session 开一条 loop-local psycopg 连接并在返回时关闭——测试每用例一次 `asyncio.run(scenario())`，跨 loop 池化会复用绑定到已死 event loop 的连接并在 suite load 下 flake；NullPool 保持 schema 隔离且不影响 production engine 配置。
- **`test_contract_compatibility.py`** — 13 端点 `ApiResponse` 信封 `{code,message,data,traceId}` 一致 + `x-trace-id` == `traceId`；`PaginatedResponse` `{items,page,pageSize,total}` 在 risks/audit；固定错误码 401`UNAUTHORIZED`/403`FORBIDDEN`/404`NOT_FOUND`/422`VALIDATION_ERROR` + trace header；weekly-report stale 响应仍守信封；真实登录设置合规 session cookie（`HttpOnly`/`Secure`/`SameSite=lax`/`Path=`/`expires=`）+ `mustChangePassword=false` + `/api/auth/session` 回读 `expiresAt` 一致；`DataScope=NONE` 返回空页不改变信封。
- **`test_authorization_matrix.py`** — 24 例四角色×端点矩阵（每角色正负例，权限图来自 `seed.ROLES`）；五 `DataScopeType` 参数化，精确项目集合比较（`titles == {f"风险-{name}" ...}`，非子集）；归档项目跨范围排除；范围外风险详情返回 404（非 leaky 403）。
- **`test_security_acceptance.py`** — CSRF：未信 origin 拒绝 logout（403 + session 不失效）与 change-password；SSRF：`OutboundEndpointGuard` 阻断 private/loopback/metadata/IPv6-loopback/IPv4-mapped、`revalidate` 检出 DNS rebinding、approved-internal 网络 allowlist 仅允许范围内；Excel 上传：非 xlsx 名 / 非 ZIP 内容 / 空 body 经真实端点 400、oversized/path-traversal/non-zip 经真实 `WorkbookStorage.validate`（`WorkbookError`）；closed Agent Provider：`_parse_transport` 对非 2xx 抛 `AgentProviderError`、每个 malformed shape（过大/非 utf8/非 json/非 dict/重复键）抛 `AgentProviderInvalidOutput`、仅 well-formed dict 接受、错误消息为固定安全串（`sk-secret`/`ignore_previous` 不泄漏）。唯一 test double：SSRF 的 `_StaticResolver`（DNS 解析桩，guard 真实地址分类逻辑仍执行）。
- **`test_audit_reliability_acceptance.py`** — 审计：真实业务写追加可验证链 link（`verify_integrity().status=="VALID"` + trace 计数 1）、append-only 不可变（真实 `UPDATE`/`DELETE`/`TRUNCATE` 各抛 `DBAPIError`，由真实 DB trigger 强制）；可靠性：幂等 enqueue（同 idempotency key → 同 task id + 单 outbox 行 + `dispatchGeneration=1`）、crashed-worker 恢复（backdated heartbeat+lease → `reconcile` → `RETRY_WAIT` + token 清除 + `nextRetryAt`）、orphan gen-0 redispatch（`create_task` gen 0 → `reconcile` → gen 1 + outbox 创建）、outbox→Celery 派发（`publish_outbox` → `send_task("risk_platform.reliability.execute", (taskId, 1))` + `publishedAt` 置位）；回滚原子性：模拟下游失败 → risk（按 `dedupeFingerprint`）/ audit（按 `traceId`）/ todo（按 `description==suggestion`）均为 None。唯一 test double：`_CeleryRecorder`（`send_task` 桩，真实 `publish_outbox` 查询/排序/`publishedAt` 变更仍执行）。
