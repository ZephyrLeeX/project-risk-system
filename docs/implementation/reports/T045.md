## 结论

T045 修复了 T033 readiness 检查发现的 systemic contract-fidelity 缺陷：三个模块（`admin/overview`、`weekly_reports`、`agent`）共享的 `_Contract` 基类其通配 `field_serializer("*", when_used="json", check_fields=False)` 携带 `-> object` 返回注解，使 Pydantic 在 **serialization-mode** JSON schema 生成时把每个字段的 schema 替换为 `object`，所有 `_Contract` 子类字段在 frozen OpenAPI authority（T032）与生成产物 `openapi.ts` 中解析为 `unknown`。FastAPI 为 response model 使用 serialization mode 生成 OpenAPI，故 ADR 0023/0021/0028/0029 的 item 级字段对前端不可见，阻塞 T033（overview）与 T034（weekly/agent UI）。

根因修复为最小实现：**仅删除三个 `_Contract` 通配 field serializer 的 `-> object` 返回注解**（并加 `# type: ignore[no-untyped-def]`，因 mypy strict 要求返回注解，而任何返回注解都会重新破坏 schema）。序列化函数体逐字节不变，runtime JSON 行为完全兼容（datetime→UTC RFC 3339 毫秒+`Z`、`when_used="json"` 保留 Python `model_dump` 返回 datetime 对象、`extra="forbid"` 不变）。re-freeze `openapi.json`/`openapi.ts` 后，受影响 schema 恢复真实字段类型（`format: date-time`/`enum`/`$ref`/`type`），API surface 不变（仍 93 paths / 243 schemas / 104 operations）。Independent Review `REVIEW_PASSED`。

## 根因（已独立验证）

`_Contract` 基类原实现：

```python
@field_serializer("*", when_used="json", check_fields=False)
def serialize_datetimes(self, value: object) -> object:   # <- 返回注解是根因
    if isinstance(value, datetime):
        return value.astimezone(UTC).isoformat(timespec="milliseconds").replace("+00:00", "Z")
    return value
```

Pydantic v2 将 `field_serializer` 的**返回类型注解**用作该字段的 serialization-mode JSON schema。通配 `*` + `-> object` 使每个字段（无论真实类型为 `datetime`/`Literal`/`UUID`/嵌套模型/`str`/`int`/`bool`）的 serialization schema 被替换为 `object`，OpenAPI 中退化为 `{"title": ...}`（无 `type`/`enum`/`anyOf`/`$ref`），嵌套模型字段退化为裸 `{}`。`openapi-typescript` 据此生成 `unknown`。

`model_json_schema()`（默认 validation mode）不受影响——这正是该缺陷在 T016/T032 验证中未被发现的原因（T032 compatibility check 仅覆盖前端已消费 path，overview/weekly/agent 端点在 T033/T034 前尚未被前端消费）。

### 修复

删除返回注解后，Pydantic 保留每个字段的声明类型作为 serialization schema，序列化函数体不变。Independent Review 与 Implementer 均经实证复现确认：`-> object` → 退化；无返回注解 → 真实类型（`{"format":"date-time","type":"string"}`、`{"enum":[...],"type":"string"}`、`{"$ref":"..."}`）。

mypy `strict = true` 要求返回注解，而唯一诚实的返回类型（`-> object`）会重新破坏 schema；故以 `# type: ignore[no-untyped-def]` 局部抑制（具体 code，`warn_unused_ignores` 下该抑制确实被使用）。这是 pydantic serializer 返回注解驱动 schema 与 mypy strict 要求返回注解之间的固有张力，最小且 base-class-only 的解决方案。
