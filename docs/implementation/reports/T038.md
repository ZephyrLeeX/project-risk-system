根因经源码逐行核实为**真实 production 容量缺陷，非 harness/env artifact**：

1. **主因 — `/api/todos` 无分页**：该端点无 `LIMIT`/`OFFSET`，对全量 scoped 结果集（11667 todos × 6 表 JOIN）**双重物化**（一次取 items、一次取 counts/summary），返回约 7.4MB JSON。孤立单请求 ~2s；50 VU 并发下 p95 飙至 6.4–9.5s，拖垮 fast_read gate 并**级联**至连接池耗尽 → mutation/admin_overview/async_dispatch/auth 跨类延迟、5xx（1.4–1.86%）、100% task retry、DB slow-query gates（>2s 查询 2262–2623 个、>500ms 占 92.4%）、pool-acquire timeout、lock wait。对照 `/api/risks` 有正确 `.offset/.limit` 分页，孤立 36ms —— 不对称真实存在。

3. **SSE heartbeat**：UNVERIFIED → FAIL。ADR 0032 §9 的有界确定性 fake AI Provider **无法在不修改 production 的前提下接线**（`composition.py:168` `build_provider` 无条件返回 `AgentProviderAdapter`，无注入点）；fast-fail 流在 ~5s 因 `ERROR` 为 terminal 事件而关闭（`events.py:38` `TERMINAL_EVENT_TYPES={COMPLETED,ERROR}`），不存在长运行流可测 keepalive 节律；`_stream` 无 transport keepalive（不发 `: ping`）。

## Independent Review

`CONFIRMED-FAIL`。独立 Reviewer 逐项对抗性核验全部 claim，确认 FAIL honest、justified、production-untouched：

1. **`/api/todos` 真无界** — `todos/service.py:62-63` `list()` 双调 `_rows()`；`_statement:191-198` 6 表 JOIN 无 `LIMIT`/`OFFSET`/`.limit()`；`schemas.py:81-85` `ListTodosQuery` `extra="forbid"` 仅 `owner/status`，harness `?page=1&pageSize=20` 被 FastAPI 静默丢弃为 dead params，端点无分页代码路径。对照 `risks/service.py:401-402` `.offset/.limit` 正确分页 → 不对称真实。11667 todos × 6 表 JOIN × 2 物化与 `db_slow_query_2s=2262` / `slow_query_ratio=92.4%` 互证。
2. **load model 忠实 ADR 0032 §9** — 50 VU、warmup 30s、measurement 150s（均 ≥ADR 下限）；fast_read composition 匹配 §1 "单实体/分页列表/dashboard/weekly read"。**将无分页 `/api/todos` 纳入 fast_read 非 methodological flaw**——§1 明确命名"分页列表"为 fast_read 目标，`/api/todos` 本应是分页端点，其无分页为真实 production 缺陷；harness 忠实发送真实 client 会发的 `page/pageSize`（被端点忽略），排除它才是 gaming gate。
3. **SSE findings honest** — (a) `agent/service.py` `_create` enqueue `AGENT_EXECUTION` 但写 0 个 `AgentEvent`；(b) `scheduler.py:64` `DEFAULT_OUTBOX_DRAIN_SECONDS=5.0` → 初始事件 drain-bounded；(c) `events.py:38` `TERMINAL_EVENT_TYPES={COMPLETED,ERROR}` → fast-fail 流 ~5s 关闭；(d) `_stream` 无 `: ping` keepalive；(e) `execution.py:229-236` 无 provider → `_fail(retryable=False)` → terminal `ERROR`；(f) `composition.py:168` `build_provider` 无条件，`FakeProvider` 仅存 tests，无 production 注入点；(g) `gates.py` `heartbeat=None`→UNVERIFIED→FAIL（§8 不得记 PASS）。
4. **production untouched** — `git diff --stat` 与 `--cached` 均空；`artifacts/` gitignored（build output，正确 untracked）。
5. **无 harness-only 修复可使 gate PASS** — `/api/todos` 延迟源于端点忽略分页并双重物化全量集，无 request-shape 变更可 bound（schema 拒 extra、service 无分页路径），唯一修复为 production（加 LIMIT/OFFSET + counts query），正确按 §10 推迟 owning task；SSE 初始事件受 5s drain cadence 下界；heartbeat 需 wireable fake provider（改 `build_provider`）或 transport keepalive（改 `_stream`），均非 harness 可解。唯一"harness fix"= 排除 `/api/todos` = gaming，非合法 pass。

### Reviewer 标注的 honest caveats（不改变 verdict）

1. **`task_retry` 100% 归属歧义** — 无 provider 路径 `retryable=False`（`execution.py:235`），AGENT_EXECUTION 任务应 `FAILED`（`attemptCount=0`，不计 retried）并被 `EXTERNAL_SUBSTITUTE_FAILURE_CODES`（`collectors.py:60`）排除为 `failed_external`；然而 `retried=65==total_terminal=65` 且 `failed_non_infra=0`。两种解释：(a) dispatcher 重试 non-retryable 失败（production concern，非 false positive），或 (b) 65 以 IMPORT_PREVIEW（真实非替身 task kind）在池饱和下重试为主。artifacts 未按 task kind 分解。**即便 task_retry 为替身 artifact，也不影响 verdict**——其余 11 项 hard-gate FAIL（5 latency 类、http_5xx、db_connection_saturation、db_lock_wait、db_slow_query_2s、db_slow_query_500ms、sse_initial_event）独立且 artifact-backed，FAIL 不依赖 task_retry。
2. **单请求 timing/size 未入 artifacts** — 2050ms/7.4MB 为 code-consistent 但未提交 `artifacts/load/`。minor——gate FAIL 本身（latency p95、slow-query 计数）artifact-backed，verdict 不依赖单请求探针。
3. **`db_lock_wait` marginal** — Run 2 测 1.079s vs 1.0s gate（79ms 越线），Run 1 未越此 gate。真实 binary breach，但方差敏感。
4. **3 类 sample-count 不足**（mutation n=116、admin_overview n=165、async_dispatch n=49，均 <500）— 为池饱和 throttle throughput 的结果而非 harness bug；但 latency 越线幅度极大（4771–6037ms vs 800–2000ms gate），thin-sample 噪声无法解释。
