## 实施摘要

- 新增共享 `KeyRing`，从调用方明确指定的只读文件路径加载 base64 编码的 32-byte
  key。每个 key 使用明确 version，且只有一个 active version；历史 key 仅用于解密。
- 新增 AES-256-GCM `SecretCipher`，每次加密生成 96-bit 随机 nonce，并将 envelope
  format/version 与 key version 作为 authenticated associated data。
- 新增 `needs_rotation()` / `rotate()`、短 secret 全掩码与长 secret 仅保留末四位的
  masking helper。
- 新增 legacy NestJS AES-GCM `ciphertext` / `iv` / `authTag` triplet 读取与一次性轮换
  adapter。legacy 数据本身没有 key version，因此调用方必须显式指定其所属历史 key
  version；不会猜测或静默使用 active key。
- 新增共享 `OutboundEndpointGuard`：Provider 强制 HTTPS 且拒绝 URL credentials、
  fragment 和非法 port；IMAP 接受独立 host/port；两者统一进行 hostname、全量 DNS
  answer 与 IP 分类校验。
- 默认拒绝 private、loopback、link-local、unspecified、multicast、reserved、IPv4-mapped
  敏感地址以及已知 metadata hostname/address。一个 DNS answer 集合中只要存在一个
  禁止地址即整体拒绝。
- 批准的内网 Provider/IMAP 必须同时匹配显式 hostname allowlist 与 CIDR allowlist；
  loopback、link-local/metadata 等危险范围即使加入 CIDR 也不能放行。
- `ResolvedEndpoint` 暴露已验证的 pinned connection address；`revalidate()` 要求每次
  connect 前重新解析，并在 answer 改变或重绑定到禁止地址时拒绝。
- redirect policy 固定为不跟随 redirect；调用方应配置 client 的 redirect mode 为
  disabled/error。Provider 子路径 helper 额外保持同 origin。
- 所有 crypto/outbound 失败仅返回稳定 error code，不包含 plaintext、ciphertext、key、
  URL、hostname、IP 或上游 exception message；模块本身不记录这些数据。

## Crypto envelope spec

持久化 envelope 是 ASCII 字符串：

```text
rpenc:v1:<key-version>:<base64url nonce>:<base64url ciphertext-and-tag>
```

- algorithm：AES-256-GCM；
- nonce：每次加密独立生成的 12 bytes；
- tag：由 `cryptography` 的 AEAD 输出附在 ciphertext 末尾；
- associated data：`rpenc:v1:<key-version>`；
- key version：`[A-Za-z0-9_-]{1,32}`，随密文持久化并受认证保护；
- base64url 字段省略 padding；
- 轮换：用 envelope 指定的历史 key 解密，再只用 active key 产生全新 envelope；
- missing key、invalid envelope、tag/tamper failure 均 fail closed。

该 envelope 是 T007 的共享 persistence value；T007 未拥有或修改 T003 schema。后续
Provider/mailbox module 负责将其写入各自已有 encrypted text field，并遵守对应 Task
的 persistence contract。

## 风险与后续集成要求

- T014/T023/T024 的真实 HTTP/IMAP client 必须在每次 connect 前调用 `revalidate()`，
  使用 `connection_address` pin 实际 socket，同时保留原 hostname 用于 TLS SNI 与证书
  校验；只在配置保存时验证一次不足以抵御 DNS rebinding。
- HTTP client 必须显式关闭自动 redirect；当前 guard 的 redirect policy 不允许同 origin
  或跨 origin redirect。
- legacy triplet 不携带 key version。若未来存在 legacy 数据，部署方必须明确指定对应
  historical key version 后才能轮换；T007 不根据单一 `DATA_ENCRYPTION_KEY` 猜测版本。
- 实际 production secret file paths、active version 和 internal allowlist 由后续批准的
  composition/deployment 配置提供，不得将真实值提交 repository。
