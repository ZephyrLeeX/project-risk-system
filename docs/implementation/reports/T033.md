## 根因（已独立验证）

### 现象

以当前 HEAD（含 T040 composition + T043/T044）经 `risk-platform-openapi` 重新导出 OpenAPI（与 frozen `packages/contracts/openapi/openapi.json` 逐字节一致，T032 已验证），`AdminOverview` 等 schema 字段缺失 `type`/`anyOf`/`$ref`/`enum`，仅保留 `title`：

```json
"AdminOverview": {
  "properties": {
    "attention": { "title": "Attention" },
    "generatedAt": { "title": "Generatedat" },
    "health": { "title": "Health" },
    "recentAudit": { "title": "Recentaudit" },
    "unavailableSections": { "title": "Unavailablesections" }
  },
  "required": ["generatedAt","health","attention","recentAudit","unavailableSections"]
}
```

`openapi-typescript` 据此生成 `attention: unknown; generatedAt: unknown; health: unknown; ...`，前端无法类型安全访问任何 item 字段。

### 根因

`apps/api-python/src/risk_platform/admin/overview/schemas.py` 的 `_Contract` 基类使用通配 field serializer：

```python
class _Contract(BaseModel):
    model_config = ConfigDict(extra="forbid")

    @field_serializer("*", when_used="json", check_fields=False)
    def serialize_datetimes(self, value: object) -> object: ...
```

该通配 `field_serializer("*", check_fields=False)` **仅在 serialization-mode schema 生成时破坏字段类型推导**。独立验证：

- `HealthItem.model_json_schema()`（默认 validation mode）→ **正确**（含 `enum`/`type`/`$defs`）。
- `HealthItem.model_json_schema(mode="serialization")` → **损坏**（字段仅 `{"title": ...}`，`link` 为 `{}`）。

FastAPI 为 response model（`response_model=ApiResponse[AdminOverview]`）生成 OpenAPI schema 时使用 **serialization mode**，故所有 `_Contract` 子类的 OpenAPI schema 被破坏，而 `model_json_schema()` 默认调用（validation mode）不受影响——这正是该缺陷在 T016/T032 验证中未被发现的原因（T032 compatibility check 仅覆盖前端**已消费**的 path，overview/weekly/agent 端点在 T033/T034 前尚未被前端消费）。

### 影响范围（systemic，非 T033 孤立）

`_Contract` 被 **三个** module 共享，故 frozen OpenAPI authority 中下列 schema **全部**损坏（字段解析为 `unknown`）：

- `admin/overview/schemas.py`（T033 surface）：`AdminOverview`、`HealthItem`、`AttentionItem`、`RecentAuditItem`、`UnavailableSection`、`OverviewLink`。
- `weekly_reports/schemas.py`（T034 surface）：`WeeklyReportResponse`、`WeeklyProjectDetail`、`WeeklyReportItemResponse` 等（已确认 `WeeklyReportResponse.freshnessDeadline` 等字段损坏）。
- `agent/schemas.py`（T034 surface）：`AgentConversationResponse`、`AgentConfirmationResponse`、`AgentConversationEnvelope`、`AgentConversationHistory`、`AgentMessagePage`、`AgentToolResult` 等（已确认 `AgentConfirmationResponse.completedAt` 等字段损坏）。

因此该缺陷**同时阻塞 T033（overview）与 T034（weekly-reports / agent UI）**作为生成类型的消费方。

## 为什么不在 T033 授权范围内修复

1. **T033 write-set = "Admin frontend files/tests only"**；Explicit out-of-scope = "backend changes"。根因修复位于 `apps/api-python/.../admin/overview/schemas.py`（backend），属 T016 frozen write-set。
2. **`_Contract` 为共享基类**：修复需同步 `weekly_reports/schemas.py`、`agent/schemas.py`，属 T027/T029 等已完成 Task 的 frozen write-set。
3. **修复必然改变 frozen OpenAPI artifact**：修正 serialization-mode schema 后，`openapi.json`/`openapi.ts` 将新增字段类型（schema-only，不改 path/method/runtime 行为），需 re-freeze T032 的 frozen authority artifact。
4. ORCHESTRATOR 协议与 T032 precedent 明确：**已完成 Task 的 write-set 冻结于 `REVIEW_PASSED`，不得扩展；缺陷应映射到新 remediation Task 或经 ADR 授权，而非由下游 Task 越界修改 frozen write-set**（参见 T032 DESIGN_GAP → 新增 T043/T044 的处理路径）。
5. 本次授权明确「不修改 T034 write-set」「不修改已冻结 contract（除非同步 OpenAPI artifacts 并通过 contracts:check，但那针对 API surface 改变，而本缺陷是 frozen authority 本身的 fidelity 缺陷，非 T033 引入的 surface 改变）」。

T033 因此无法在自身 write-set 内满足 acceptance criteria「All admin pages pass real-API E2E including degraded/empty/forbidden states」——overview 的 degraded/empty/**forbidden**（ADR 0023 `unavailableSections`/`FORBIDDEN` partial-data）状态必须经 `GET /api/admin/overview` 的 typed item 字段呈现，而该生成契约当前不可用。
