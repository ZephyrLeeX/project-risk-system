## 实施摘要

- 新增 disjoint 子包 `mailbox/sync_results/`（`schemas.py`、`service.py`、`api.py`、`__init__.py`），
  迁移 NestJS `mail-sync-results` 的 7 个浏览/重试端点，复用既有 `@risk-platform/contracts` 类型，
  不新增持久化、不新增 ADR。
- 端点：`GET /mailbox/sync-summary`、`/review-options`、`/messages`、`/messages/{id}`、
  `POST /messages/{id}/retry`、`/sync-batches`、`/sync-batches/{id}`，全部挂载于全局 `/api` 前缀下。
- 权限/scope：class `mailbox.sync_self` 经 `require_permissions` 守卫；`MailSyncResultsService`
  对**所有**操作先校验 `RISK_ADMIN` 角色（与 NestJS `ensureRiskAdmin` via `getConfig` 一致），
  再以 `MailboxConfig.userId == identity.user.id` 限定自身配置 scope。
- 分页/错误信封：`ApiResponse{code,message,data,traceId}` 与 `PaginatedResponse{items,page,pageSize,total}`；
  `ApiError` 403/404/400 语义与 NestJS `ForbiddenException`/`NotFoundException`/`BadRequestException` 一致。
- ADR 0022 retry/handoff：retry 仅接受 `MailMessageStatus.FAILED`，拒绝并发 `QUEUED/RUNNING` 批次，
  以 `(uidValidity, imapUid)` source-identity 定位 `MailSourceHandoff`，按失败 stage 选择
  `ATTACHMENT_PARSE` 或 `MAIL_AI_REVIEW_PUBLISH`（`_retry_stage`），重置该 stage 为 `PENDING` 并清除
  failure 诊断，经 `enqueue_task` 以 fresh uuid idempotency key（ADR 0018）入队，创建 `RETRY` 批次
  （`retryOfId`/`targetMessageId`/`startUid`/`endUid`），audit `MAIL_MESSAGE_RETRIED`（ADR 0017 metadata-only）。
- composition：`composition.py`/`main.py` 仅做 additive 注册（`mail_sync_results_service` +
  `mailbox_sync_results_router`），不改动 T040 冻结逻辑；`tests/test_composition.py` 同步期望 service 集。

## Independent Review

逐行比对 NestJS `mail-sync-results.controller.ts`/`.service.ts`：summary/reviewOptions/messages/message/
batches/batch/retry 映射、`mapBatch`/`mapMessage`/`mapMessageDetail`/`mapMatch`/`mapCandidate`、
`resultLabel`/`resultNote`/`levelLabel`、`batchCode`、maskedEmail、`historicalFailedCount` 均一致。

发现并修正一项偏差：初版在 retry endpoint 内 `message.retryCount += 1`，而 NestJS 在
**processor**（`mail-sync-processor.service.ts:203`，status→ANALYZING 时）递增，endpoint 本身不递增。
已移除该递增以忠实于 reference；`retryCount` 递增属 T024–T026 pipeline 职责，FastAPI worker 目前未递增
（既存缺口，out of T043 scope）。

确认的批准偏差（非 regression）：
- audit 为 ADR 0017 metadata-only（NestJS 记录 afterSnapshot；FastAPI 不记录 snapshot）。
- retry 经 `enqueue_task` 触发 per-stage 任务（ADR 0022 UID-only durable handoff），而非 NestJS
  `processor.queue(batch.id)` 重跑整批。
- retry 对 `uidValidity IS NULL` 提前 400（ADR 0022 source-identity re-fetch 所需；NestJS 重跑整批无对应守卫）。
- 批次 code 使用 `MAIL-RETRY-…`，与 FastAPI 既有 `MAIL-`/`MAIL-SCHEDULED-` 族一致（NestJS 用 `SYNC-`）。

结果：`REVIEW_PASSED`，无 unresolved `DESIGN_DEVIATION`。
