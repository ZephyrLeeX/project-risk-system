## 批准的 REPORT category contract

ADR 0029 将 PostgreSQL 当前 active `RiskCategory` 定为 `REPORT.categoryId` 唯一权威来源。Agent
复用 ADR 0026 `RISK_CATEGORY_OPTIONS_V1`，Provider 仅选择 attempt-local opaque option；服务端映射为
本地 UUID，并把 `categoryId` 与 `categoryBindingDigest` 纳入 ADR 0019 canonical content、content digest
和一次性 token 绑定。

preview 签发前与 confirmation transaction 内都重新校验分类。缺失/未知 option 非 retryable；签发前
mapping stale 按既有 `AGENT_EXECUTION` budget 重试并重建 options；确认时 missing、disabled 或 binding
stale 返回 `AGENT_CONFIRMATION_CONTENT_MISMATCH`，不消费 token 且不产生业务写入。不存在默认分类、
文本推断、自由 taxonomy、历史或 legacy fallback。

协议显式升级为 `AGENT_PROVIDER_EXECUTION_V2`；V1 response 和缺少分类绑定的 legacy `REPORT` token
fail closed。confirm endpoint、空 request、TTL、owner/scope、replay、SSE envelope 以及
`PROCESS`/`RESOLVE` 业务语义保持兼容。audit/log 仅增加固定 version/count/failure code，不保存 option
集合、UUID mapping、分类文本、canonical content 或 Provider output。

## Remediation 结果

上一轮 `REVIEW_FAILED` 的五个 findings 已在限定范围内全部修复并验证：

- `RISK_CATEGORY_OPTIONS_V1` projection item 严格复用 ADR 0026 的 `option_id` / `name` /
  `description` / `default_level`（snake_case），无 camelCase、UUID、code、keywords 泄漏；选项按
  `sortOrder ASC, code ASC, id ASC` 排序并连续映射为 `C1..Cn`。
- `PreviewContent` 对 REPORT 的 missing / empty / 非标量 / 多个 / unknown `categoryOptionId` 全部
  fail closed；`PROCESS` / `RESOLVE` 显式携带 `categoryOptionId`（含 `null`）经 `model_fields_set`
  判定拒绝，不静默接受。
- `AGENT_REPORT_CATEGORY_STALE` 形成闭环：preview 签发前分类删除 / 禁用 / 绑定变更 → retryable
  `DurableTaskFailure`；retry 完整重跑 attempt 并从 PostgreSQL 重建 option 集合（不复用旧 mapping）；
  耗尽后按 `finish_task` 的 `attemptCount >= maxAttempts` 进入 `FAILED` retry-exhausted 终态。
- legacy REPORT token（缺 `categoryId` / `categoryBindingDigest`）按
  `AGENT_CONFIRMATION_CONTENT_MISMATCH` fail closed；`PROCESS` / `RESOLVE` canonical 固定携带两个
  null 字段。
- confirmation 单 token `FOR UPDATE NOWAIT` 严格并发（并发第二消费方
  `AGENT_CONFIRMATION_IN_PROGRESS`）；business mutation + `RISK_CREATED`/`RISK_RESOLVED`/
  `ACTION_ITEM_UPDATED` + `AGENT_*_CONFIRMED` audit 同事务，注入 audit 失败时 risk / token / audit
  原子回滚。
