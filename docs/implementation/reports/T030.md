## Readiness blocker

T030 的 `REPORT` 已批准 canonical content 只包含 `operation`、`projectId`、`riskId`、`todoId`、`title`、`description`、`riskLevel`、`dueDate` 和 `assigneeUserId`。ADR 0020 对 `REPORT` 的必填字段同样只有 `projectId`、`title`、`description` 与 `riskLevel`。

正式 `Risk` 必须持有有效 `categoryId`，T022 的现有 `RiskCreate` 也强制要求 `category_id`。当前批准设计没有为 Agent `REPORT` 定义 category selection、受控 option projection、默认分类或确定性映射，因此该操作无法仅通过现有领域服务表达。自行选择默认分类、按文本推断分类，或扩大 canonical/API contract 都会改变批准的业务与安全边界。

这满足 T030 stop condition：“An approved operation cannot be expressed through the existing domain services”。需要批准设计补充 Agent `REPORT` 的分类来源、内容绑定方式及确认时的失效/重检语义后，T030 才能进入 `READY`。
