## 实施结果

新增有界、可重试的 `RETENTION_CLEANUP` durable task/outbox entry point，以及导入源、Agent 完整会话和
`risk-mail-*` orphan temp 的 fixed-clock cleanup service。每个导入/会话删除均复用 ADR 0027 的 resource
advisory lock → resource fact row → hold row 顺序，在事务内重新判定 hold、rollback window、active task 和
未消费确认凭证。业务批次、业务结果和 audit rows 均继续保留。

导入文件使用显式绝对 storage root、UUID 固定目录、拒绝 symlink 的目标解析，以及
`retention-deleted:<id>` → `retention-complete:<id>` 两阶段状态。文件删除与数据库提交间的 crash window
通过固定 marker 收敛；目录缺失、空目录、marker、unexpected residue 均 fail-closed 区分。失败 recovery 与
正常到期候选各自有独立 bounded PostgreSQL 查询，避免 partial failure 饥饿。Dry-run 不修改数据库或文件。
