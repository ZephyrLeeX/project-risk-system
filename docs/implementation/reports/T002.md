## Review 历史与第一轮修复

第一轮独立 Review 结果：`REVIEW_FAILED`。

第一轮 findings 及修复：

1. 高：unknown input 约束仅存在于测试私有 DTO，未形成共享 core contract。
   - 新增 `StrictRequestModel`，以 `ConfigDict(extra="forbid")` 作为所有 feature
     request DTO 应继承的共享基类；没有使用全局 monkeypatch。
   - composition test router 的 `StrictInput` 已实际继承该基类，并验证 unknown
     body field 返回统一 422 envelope/trace。
2. 高：FastAPI 的 catch-all exception handler 位于 Starlette
   `ServerErrorMiddleware` 内部处理链之外，响应后仍可能向 ASGI server 重新抛出
   包含 secret 的原异常。
   - 移除通用 `Exception` handler，新增位于 `ServerErrorMiddleware` 内侧的
     `SafeExceptionMiddleware`。
   - middleware 仅捕获 `Exception`，不捕获 `BaseException` 或 cancellation；普通
     未处理异常被消费并转换为脱敏四字段 500，日志只记录 trace ID。
   - probe 使用 `raise_app_exceptions=True`，证明原始异常不传播，且 response/log
     均不包含原始异常文本；独立 `BaseException` probe 证明控制流不会被吞掉。
3. 中：tracing 未覆盖 CORS preflight，且允许 origin 的 500 不保证 CORS headers。
   - middleware 层次调整为 trace → CORS → safe catch-all → trusted proxy → app。
   - 新增 OPTIONS trace 和允许 origin 的脱敏 500 CORS/trace 一致性测试。
4. 低：401/403、`WWW-Authenticate`、detail 脱敏及 404/405 回归不足。
   - exception mapping 注册到 Starlette `HTTPException`，覆盖 framework 404/405。
   - 新增 401/403 envelope/trace、detail 脱敏、`WWW-Authenticate` 保留、unknown
     route 404 和 method 405 tests。

第二轮独立 Review 已重新检查最新 diff、测试和报告，并复跑全部 Python 质量门。
第一轮四项 findings 均已关闭，最终结果：`REVIEW_PASSED`。

## 实施摘要

- 新增 `create_app()` FastAPI factory 和 `risk_platform.main:app` ASGI 入口。
- 所有 feature router 统一挂载到 `/api`；`AppComposition` 明确定义 router、
  dependency override 和 lifespan 三个组合点。模块测试及 T040 可在不修改共享
  bootstrap 的情况下组合模块。
- 新增只读取 T002 所有配置项的不可变 `Settings`：运行环境、API 端口、明确的
  CORS origins、明确的受信代理 CIDR、session Cookie 名称。配置错误只报告字段名，
  不回显原始值。
- 新增 `{code,message,data,traceId}` Pydantic envelope、`ok()` helper 和
  `/api/health` 静态进程 liveness。健康数据保持 legacy `HealthResponse` 字段和
  `project-risk-api` identity；未探测 PostgreSQL、Redis、Worker 或外部服务。
- 新增共享 `StrictRequestModel`。后续 feature request DTO 必须显式继承该基类，
  以局部、可测试的方式拒绝 unknown fields。
- 新增 request-scoped UUID trace middleware。合法 `X-Trace-ID` 可传播；无效值会
  被替换；响应 header 与 envelope 使用同一 trace ID。
- 新增 validation、Starlette HTTP、显式 `ApiError` 映射，以及位于
  `ServerErrorMiddleware` 内侧的安全 catch-all ASGI middleware。所有 JSON 错误均
  使用统一 envelope；validation input、HTTP detail 和未处理异常正文不会进入响应
  或日志，普通未处理异常不会继续传播到 ASGI server。
- CORS 仅允许明确配置的 HTTP(S) origin，并启用 credentials；禁止 wildcard。
- forwarded client/protocol headers 仅在直接连接来源位于明确配置的
  `TRUSTED_PROXY_CIDRS` 时生效，并从可信代理链右侧选择首个非受信来源。
- 提供 session Cookie 安全默认 contract：`HttpOnly`、`SameSite=Lax`、`Path=/`，
  production 强制 `Secure`。认证 token、session persistence 和认证业务仍由 T009
  负责。
- 增加 19 个 focused HTTP/config/security/composition/OpenAPI tests，并锁定当前
  Starlette ASGI test transport 所需的 `httpx2` 开发依赖。

## 风险与限制

- 当前锁定版本为 FastAPI 0.141.1 / Starlette 1.6.0。Starlette 已弃用以旧
  `httpx` 驱动同步 `TestClient`，且该路径在当前环境对最小应用会挂起；focused
  tests 使用 Starlette 当前支持的 `httpx2.ASGITransport` 直接驱动 ASGI，并显式
  进入 app lifespan。该问题不影响应用运行路径，但后续测试应复用当前 transport
  方式或等待上游同步 client 修复。
- production 反向代理网段必须通过 `TRUSTED_PROXY_CIDRS` 明确配置；空值的安全
  默认行为是不信任任何 forwarded header。T040 deployment 必须提供实际网段，
  不应配置宽泛公网 CIDR。
- T009 集成 session Cookie 时应复用 `session_cookie_options()`；不得降低 production
  `Secure` 默认值。
