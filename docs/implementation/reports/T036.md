## 结论

T036 在其批准 write-set（`project-risk-system/infra/backup/**` + 专属 backup tests/runbook）内 materialize 了 ADR 0031 加密备份/恢复契约（设计 §9，ADRs 0008/0009/0014/0027/0031）：quiesce 协调的一致备份集合（PostgreSQL `pg_dump -Fc` + durable 文件 tar）、AES-256-GCM 信封加密（per-backup DEK 被 versioned 备份 KEK 经 T007 `rpenc`/`KeyRing` 包装）、manifest 绑定的三层完整性、版本化 KEK 与保留历史可恢复性（不 re-encrypt）、fail-closed 隔离恢复（密钥查找 + AEAD/sha256/manifest 三层校验 + 审计哈希链校验 + 文件 reconcile + 部分集合中止）。备份权威 = PostgreSQL + durable 文件存储；Redis/Celery/cache/temp/log 明确排除；密钥材料绝不进入制品/仓库/日志。Independent Review `REVIEW_PASSED`，无 blocking finding。Wave 23 Integration 未启动。

## 实现摘要

实现为 one-shot operator package `risk_backup`（`python -m risk_backup`），复用既有 image（`postgres:16-alpine` 提供 `pg_dump`/`pg_restore`、`risk-platform-api:0.1.0` 提供 `cryptography` + `risk_platform.shared.crypto`），未新增 Compose service、未修改 `infra/docker-compose.yml`、未触碰 T035/T040/T046 frozen write-set、未实现 WAL/PITR/`pg_basebackup`。

- **`envelope.py`**：`RPBK1` 魔数 + 分块 AES-256-GCM payload。每备份一个随机 256-bit DEK，由 versioned 备份 KEK 经 T007 `rpenc` 格式包装（KEK 版本作为 AAD）。manifest 作为第一个组件加密；数据组件 AAD = 规范 manifest 字节 + 组件名 + 块序号，组件替换/重排可检出。三层完整性：DEK-wrap GCM tag + 每块 GCM tag + manifest sha256。nonce 由 per-component 随机基 XOR 块序号派生（无 (key,nonce) 复用）。外层头仅含魔数/格式版本/KEK 版本/包装后 DEK（+ 非敏感结构字段），绝不含密钥。AEAD 失败 → `ARTIFACT_AEAD_AUTH_FAILED`。
- **`keys.py`**：`BackupKeyRing` 从宿主只读文件加载 256-bit KEK（`KeyRing.from_files`），**不从环境变量读取**，与 `DATA_ENCRYPTION_KEY` 相互独立。active 加密版本 + retained decrypt 版本；`wrap_dek`/`unwrap_dek` 复用 T007 语义；历史备份靠 retained 版本可恢复，不 re-encrypt。
- **`backup.py`**：quiesce 协调捕获序列（quiesce → confirm → `pg_dump -Fc` → tar durable files → manifest → encrypt → cleanup → unquiesce）。任一失败 → `INCOMPLETE` 且删除部分制品；仅当完整加密/hash/manifest 校验通过才置 `USABLE`。明文临时目录与输出目录分离，成功**与**失败均清理；清理失败 → 制品仍 `USABLE` + SEVERE `CleanupWarning`。quiesce 确认失败 fail-closed，不产出 usable 备份。
- **`restore.py`**：fail-closed 恢复到隔离空目标（独立 DB + 独立存储，**不覆盖在线系统**）。序列：读外层头 → KEK 版本查找（`MISSING_KEK_VERSION`）→ unwrap DEK → 解密 payload → 解析 manifest（`MANIFEST_INVALID`）→ 校验（格式版本/status `USABLE`/组件齐全/alembicHead）→ 组件 sha256 校验（`PGDUMP_HASH_MISMATCH`/`FILES_HASH_MISMATCH`）→ `assert_database_empty` + `_assert_storage_empty` → `pg_restore` → 审计哈希链校验（`AUDIT_CHAIN_BROKEN`）+ alembic head 匹配（`ALEMBIC_HEAD_MISMATCH`）→ 解包 files → reconcile（`RESTORE_MISSING_REFERENCED_FILE`）。部分集合中止，不部分恢复。
- **`manifest.py`**：`backupId` = `<type>-<UTC YYYYMMDDTHHMMSSZ>-<8hex>`，8hex 取 manifest 绑定内容（`{type}:{alembic_head}:{pg_sha256}:{files_sha256}`）的摘要以解开“backupId 在 manifest 内”的循环，同时保持确定性/可排序/唯一；charset `[A-Za-z0-9_-]`，长度 1–128，为 ADR 0027 `BACKUP_COPY` 稳定标识。`backupType`/`retentionClass` 仅元数据，不自行决定 DG-05 数值或 ADR 0009 7/4/12。manifest 必含字段齐全（`manifestFormatVersion`/`backupId`/`backupType`/`createdAt`/`pg`/`files`/`encryption`（仅 `kekKeyVersion`，无密钥材料）/`retentionClass`/`status`/`createdBy`/`traceId`）。
- **`archive.py`**：确定性 tar（mtime/uid/gid 置零、排序）；`extract_files` 路径穿越守卫（`FILES_ARCHIVE_PATH_ESCAPE`）；`TarError` → `FILES_ARCHIVE_CORRUPT`；`DEFAULT_EXCLUDES` 排除 `__pycache__`/`*.tmp`/`*.log` 等。
- **`reconcile.py`**：恢复时丢弃 DB 不引用的 orphan 文件，校验 DB 引用文件均存在；不一致 fail-closed。引用源为 `import_batches.storageKey`（ADR 0031 §1 文件存储范围 = import 源）。
- **`db.py`**：psycopg 同步；`alembic_head`/`schema_hash`/`audit_chain_status`（复用 `audit_log_compute_hash` SQL + lag window，ADR 0008）/`import_storage_keys`/`assert_database_empty`。
- **`quiesce.py`**：`ComposeQuiescer`（停 scheduler/worker；API 一致性以停止 `api` 容器实现，见下 Non-blocking observations）与 `NoopQuiescer`。
- **`cli.py`**：metadata-only JSON 日志到 stderr（`backupId`/`backupType`/时间/KEK **版本**（非密钥）/组件名·大小·sha256/`status`/操作者/测量 RTO/error code）。绝不记录 KEK/DEK/明文/文件内容/dump 内容。备份创建/恢复为运维事件，不写入 PostgreSQL 业务审计链（ADR 0017）。

### Non-blocking observations（不 gate checkpoint，归属 follow-up）

1. **Quiesce 模型（ADR §2 vs §11/§12）**：ADR §2 描述 API maintenance 态（读允许），实现 `ComposeQuiescer` 以完全停止 `api` 容器实现。这是对 ADR 内部张力的可接受、已记录的 resolution（§2 想要 maintenance 态；§11/§12 禁止修改实现 maintenance 态所需的 frozen API write-set），对一致性不变式严格更强，不违反任何 frozen security constraint。rationale 记录于 `quiesce.py`/`README.md`。worth architect acknowledgment but safe。
2. **backupId 哈希来源（ADR §7）**：取 manifest 绑定内容的摘要而非字面 manifest-sha256，以解开 backupId-in-manifest 循环；sound，所有 stated 性质（确定性/可排序/唯一）保留。
3. **SEVERE cleanup warning + CLI exit 0**：`cmd_backup` 在制品 `USABLE` 即使存在 `cleanup_warning`（`PLAINTEXT_CLEANUP_FAILED`）时返回 0。ADR §9 允许此情形 USABLE，但自动化 cron 可能将 exit 0 视为干净成功而忽略人工 scrub。建议为 SEVERE-cleanup 情形使用 distinct 非零 exit code 以便 automation flag。运维加固，非 correctness/security defect。
4. **reconcile 仅引用 `import_batches.storageKey`**：与 ADR §1 文件存储范围（import 源）及 documented assertion 一致，但假设无其他表引用 durable 存储文件。若未来 schema 新增其他 durable-file 引用，reconcile 会静默丢弃。architect 应确认 schema 边界；当前 ADR scope 内可接受。
5. **外层头携带结构元数据**（aead/chunkMaxBytes/components）：超出 §4 字面列举的“魔数/版本/KEK 版本/包装 DEK”，但均为解析容器所需的非敏感格式字段，无密钥/明文暴露。cosmetic。
