### 缺口确认与修复

此前 `AgentConversation` / `AgentMessage` 虽已持久化完整 USER/ASSISTANT 对话，
`AgentConversationService.history()` / `message_page()` 也可读取，但
`NativeAgentExecutionWorker` 只按 `AgentExecutionConfig.userMessageId` 加载当前消息，
`ReadOnlyAgentCore.run()` 只构造 SYSTEM、当前 USER/resume 和本轮 TOOL messages；历史消息从未进入
Provider request。因此 persistence 不是 model conversational context，短续问“第二个展开”“这个项目”
会丢失 referent，且 `max_context_size=64 KiB` 只会在超限后直接失败，没有压缩能力。

本轮新增 provider-neutral `ConversationContextService`：历史唯一读取源为 PostgreSQL，按 sequence
加载当前 USER message 之前的完整 USER→ASSISTANT turns，不加载 event、heartbeat、SSE、durable payload、
provider config 或以前 execution 的 raw TOOL messages。Core 的 Provider message 顺序现在固定为：
SYSTEM policy → durable summary（若有，明确标注为不可信业务事实）→ recent raw USER/ASSISTANT → current
USER → current execution tool loop。PROJECT_SELECTION resume facts 也从 USER 文本移入 server SYSTEM execution
context，并继续以结构化 `selected_project_id` 执行 code-level tool restriction。

### Context budget 与 compression

统一 `ContextBudget` 默认值：

- `hard_context_budget=64 KiB`
- `system_reserve=12 KiB`
- `current_user_reserve=8 KiB`
- `tool_result_reserve=24 KiB`
- `output_safety_reserve=4 KiB`
- 推导 `history_budget=16 KiB`
- `compression_trigger=14 KiB`
- `compression_target=8 KiB`

旧的 `48 KiB single / 96 KiB total tool result / 64 KiB hard context` 冲突已移除；本轮 tool loop
总结果最多使用统一的 `24 KiB` reserve。hard limit 的安全错误改为
`AGENT_CONTEXT_TOO_LARGE`。最近窗口按 UTF-8 byte budget 反向选择完整 turns，至少保留最近 2 个完整
turn 加 current USER，不拆 USER/ASSISTANT 配对。

超过 trigger 时只压缩最旧 completed turns，保留最近 2 turns；摘要通过 Provider V2 和本 execution
同一 immutable candidate snapshot 生成，请求无 tools，SYSTEM 摘要规则与 USER transcript 分离以抵抗
prompt injection。摘要输入、输出均 bounded。持久化采用 conversation row lock 和
`contextSummaryVersion/contextSummaryThroughSequence` monotonic compare-and-set；durable retry 不会覆盖更晚
summary。Provider compression 失败只记录无正文的
`AGENT_CONTEXT_COMPRESSION_DEGRADED`，随后使用 persisted summary + bounded latest raw turns 继续当前问题。

### Persistence 与 activeProject grounding

Alembic head `20260819_0017` 为 `agent_conversations` additive 增加：

- `contextSummary TEXT NULL`
- `contextSummaryThroughSequence INTEGER NOT NULL DEFAULT 0`
- `contextSummaryVersion INTEGER NOT NULL DEFAULT 0`
- `contextUpdatedAt TIMESTAMPTZ NULL`
- `activeProjectId UUID NULL`（FK `projects.id`, `ON DELETE SET NULL`）
- `activeProjectName VARCHAR(255) NULL`

旧 conversation 无 backfill/dual write，默认 summary `NULL`、through/version `0`。新 conversation 不继承
任何其他 conversation memory。

PROJECT_SELECTION 的 SELECT 或唯一授权 `project_search` 成功后，server 将已验证的 `{id, name}` 更新为
conversation activeProject。下一轮只有“这个项目/该项目/刚才的项目”等显式指代才启用结构化 project
grounding；显式提到其他项目仍正常解析。每次使用前通过 `ProjectsQueryService.detail(identity, id)` 重新
执行当前 permission/DataScope 校验；scope 撤销后立即忽略并清除旧 activeProject，不能绕过 RBAC。
用户纠正“不是 A，我说的是 B”会以本轮授权 `project_search` 的唯一结果刷新 activeProject。

### Freshness / provenance / mutation boundary

SYSTEM policy 明确 history/summary 仅用于 conversational intent、指代、用户选择和已确认意图；项目状态、
风险状态/数量、金额、待办状态和周报均可能 stale，当前回答依赖这些事实时必须重新调用本轮授权 tool。
以前轮次的 `toolInvocationId` 不会进入 current execution provenance。摘要 prompt 禁止把 AI proposal 写成
用户确认；写操作仍只能通过 proposal → `WRITE_CONFIRMATION` → server commit，context compression 自身无
tools、无业务写入，不改变 RBAC/DataScope/tool grounding/mutation confirmation 边界。
