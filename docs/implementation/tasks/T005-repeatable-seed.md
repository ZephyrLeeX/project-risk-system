# T005 — Implement repeatable Python Seed
- **Task ID:** T005
- **Title:** Implement repeatable Python Seed
- **Status:** READY / TODO
- **Objective:** Seed empty databases reproducibly with approved departments, permissions, four roles, risk rules and initial administrator.
- **Design baseline:** Design §§5,10(2); current demo data is not migrated.
- **Authoritative source references:** `apps/api/prisma/seed.ts`; current role/permission policy tests and contracts.
- **Relevant ADR IDs:** 0001, 0004, 0010, 0015.
- **Dependencies:** T002, T003.
- **Scope:** Idempotent seed command, protected admin credential input, deterministic reference records and tests.
- **Explicit out-of-scope:** Importing legacy/demo rows; printing/resetting passwords; new roles/permissions.
- **Expected read set:** Prisma Seed, schema, role policies, environment examples.
- **Expected write set:** Python seed module/CLI, tests and command docs.
- **Contracts/invariants:** Four role codes; five scopes; initial password never logged and must change; rerun does not overwrite admin password.
- **Acceptance criteria:** Twice-run Seed yields identical reference data; missing/weak secrets fail safely.
- **Validation:** Empty PostgreSQL migrate+seed twice; fixture assertions; log secret scan.
- **Required deliverables:** Seed CLI, tests, usage documentation.
- **Stop conditions:** Seed sources conflict on role permission semantics.
- **Known integration risks:** T010 permission code parity and T011 admin behavior.
