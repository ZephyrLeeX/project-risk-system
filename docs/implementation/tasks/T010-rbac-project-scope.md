# T010 — Migrate RBAC and project data scopes
- **Task ID:** T010
- **Title:** Migrate RBAC and project data scopes
- **Status:** READY / TODO
- **Objective:** Implement reusable permission enforcement and the five approved project-scope filters.
- **Design baseline:** Design §§3,5,7; `CONTEXT.md` project data scope.
- **Authoritative source references:** legacy `rbac/**`, role policy, Prisma Role/Permission/UserRole/UserProjectScope/Project, Seed.
- **Relevant ADR IDs:** 0004, 0011, 0013, 0015.
- **Dependencies:** T003, T005, T009.
- **Scope:** Current identity, permission dependency, SQL scope predicates and scoped-resource existence helpers.
- **Explicit out-of-scope:** Department scope, admin CRUD, domain endpoints, Agent orchestration.
- **Expected read set:** Named RBAC/schema/tests and contracts.
- **Expected write set:** Python RBAC module and matrix/integration tests.
- **Contracts/invariants:** ALL/OWNED/ASSIGNED/OWNED_OR_ASSIGNED/NONE only; permission and data scope separate; no existence leak.
- **Acceptance criteria:** Four-role/five-scope matrix passes for list/count/detail and forbidden/not-found cases.
- **Validation:** PostgreSQL query tests and request dependency tests; Ruff/mypy/pytest.
- **Required deliverables:** Guards/dependencies, predicates, test fixture matrix.
- **Stop conditions:** Any endpoint would require “指定部门” or implicit department authorization.
- **Known integration risks:** Incorrect joins can duplicate rows/counts; all consumers must reuse predicates.
