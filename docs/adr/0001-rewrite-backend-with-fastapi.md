# 使用 FastAPI 重写后端

项目将使用 Python FastAPI 重写现有的 NestJS/Prisma 后端，以满足采用 Python 技术栈的目标。当前系统尚未投入正式使用，因此 NestJS 后端只作为开发期间的业务行为和接口契约参照；正式上线只运行 Python 后端，不设计生产双写或线上流量迁移。

## Consequences

- 新后端应放在独立目录中，与现有后端并行开发和验证。
- FastAPI 应兼容现有 `/api` 路径、请求字段、响应结构、Cookie 登录方式、错误码和分页格式，原则上不要求前端为后端重写而改造。
- 现有前端、共享契约、数据库模型及测试用例是迁移输入，不代表可以机械翻译实现。
- 现有数据库只有演示和测试数据；新后端使用可重复执行的初始化与 Seed，不迁移旧数据。
- 按基础设施与契约、认证与权限、系统管理、项目与导入、风险与待办、邮箱与 AI、Agent 与周报的顺序迁移；每个阶段均与旧实现进行对照验收。
- 新后端同时补齐服务端 Agent、真实周报联动和管理概览动态数据，不能把现有静态或模拟行为当作目标实现。
- 新后端完成接口兼容和业务验收后，NestJS 实现退出正式交付范围，但其代码可保留为历史参照。
