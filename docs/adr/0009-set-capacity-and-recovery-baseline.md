# 设定中型容量与单机恢复基线

首期按不超过 300 名用户、5,000 个项目和每周 1,000 封周报设计与验收。单台内网服务器采用每日 PostgreSQL 加密备份和文件存储同步备份，目标 RPO 为 24 小时、RTO 为 4 小时；备份保留最近 7 个日版本、4 个周版本和 12 个月版本。

## Consequences

- 核心查询、分页、统计和后台任务必须使用接近容量上限的数据集进行性能验收。
- 上线前及此后每季度执行恢复演练；只有实际恢复并核对数据、文件和审计链后，备份才视为有效。
- 当前不承诺多实例高可用或接近零数据丢失；若目标提高，需要重新评估 WAL 持续归档、热备和部署拓扑。
