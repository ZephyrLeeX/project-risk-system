# 使用模块化 FastAPI 单体与 Celery Worker

新后端采用模块化单体：一个 FastAPI 应用按认证、权限、项目、导入、风险、邮箱、Agent 等业务边界组织，耗时和可重试工作由独立 Celery Worker 执行，Redis 作为消息代理。该结构适配单台内网服务器和分阶段迁移，同时避免微服务带来的部署与分布式一致性成本。

## Consequences

- API 与 Worker 共享领域规则和 PostgreSQL 数据，但使用独立进程运行。
- Excel 导入、邮箱同步、附件解析和 AI 调用必须建模为可重试任务，不依赖 Web 请求进程持续存活。
- PostgreSQL 保存业务任务及处理状态；Redis 不作为业务事实来源，队列消息必须可以从数据库状态恢复。
- 模块之间通过明确的服务边界协作，不跨模块随意访问数据表。
