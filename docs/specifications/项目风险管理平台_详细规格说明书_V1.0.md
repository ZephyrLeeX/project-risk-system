## 1. 文档说明

### 1.1 编制目的

本文档以当前已经完成并逐页确认的高保真交互原型为唯一页面基线，描述项目风险管理平台的页面结构、字段、交互、业务规则、权限、数据来源、响应式规则和验收要求。

本文档用于解决以下问题：

1. 确保正式开发不改变已确认的业务模块。
2. 确保前端、后端、测试对页面字段和交互理解一致。
3. 确保用户、权限、Excel、邮箱、AI和审计能力与页面入口对应。
4. 确保桌面端和手机端均按最新确认效果实现。
5. 明确高保真原型与正式系统之间需要接入的真实服务。

当不同材料描述不一致时，按以下顺序处理：

1. 用户最新确认意见。
2. 当前 11 个页面及其最新交互代码。
3. 本详细规格说明书。
4. V1.3 功能清单。

### 1.4 范围边界

业务端只保留两个核心业务模块：

1. Web 风险看板。
2. Agent 智能对话。

后台管理和风险管理员邮箱能力用于支撑上述业务模块运行，不作为新的业务域。首版不新增独立项目管理、独立任务中心、独立 AI 审核中心、BI 报表、多租户、计费和复杂审批流。

## 2. 系统概述

### 2.1 产品目标

平台通过项目清单和回款 Excel、风险管理员个人邮箱、项目经理日常上报以及 AI 风险提取，形成统一的项目风险清单、重点关注、回款关联、管理者待办和智能查询能力。

### 2.2 核心数据流

1. 系统管理员导入项目清单和回款 Excel。
2. 系统校验、匹配并发布最新有效数据批次。
3. 风险管理员配置个人邮箱并同步项目周报。
4. AI 从周报正文和附件中提取显式及隐含风险。
5. 项目经理通过 Agent 日常上报、查询和解除风险。
6. 风险、项目、回款、周报和待办数据实时汇总到 Web 风险看板。
7. 所有敏感操作写入审计日志。

### 2.3 页面组成

| 序号 | 页面 | 文件 | 主要角色 |
|---|---|---|---|
| 01 | 登录 | `01-login.html` | 全部用户 |

| 03 | 后台管理首页 | `03-admin-dashboard.html` | 系统管理员 |
| 04 | 用户管理 | `04-user-management.html` | 系统管理员 |
| 05 | 角色权限 | `05-role-permissions.html` | 系统管理员 |
| 06 | 项目数据导入 | `06-project-import.html` | 系统管理员 |
| 07 | API Key 管理 | `07-api-key-management.html` | 系统管理员 |
| 08 | 系统配置 | `08-system-config.html` | 系统管理员 |
| 09 | 审计日志 | `09-audit-logs.html` | 系统管理员、授权审计员 |
| 10 | 个人邮箱配置 | `10-mailbox-settings.html` | 风险管理员 |
| 11 | 邮箱同步结果 | `11-mail-sync-results.html` | 风险管理员 |

## 3. 角色、权限与数据范围

### 3.1 默认角色

| 角色 | 默认数据范围 | 主要能力 |
|---|---|---|
| 系统管理员 | 全部项目 | 后台管理、Excel导入、API Key、系统配置、审计 |
| 风险管理员 | 全部项目 | 完整看板、Agent、风险维护、个人邮箱和周报同步 |
| 项目经理 | 本人负责及被授权项目 | 查看、查询、上报、处理和解除风险 |
| 查看/审计员 | 被授权项目 | 只读查看风险、回款、周报和审计信息 |

### 3.2 权限原则

1. 前端菜单权限和后端接口权限必须同时校验。
2. 用户无权限时不显示入口；直接访问地址时返回无权限页面或 `403`。
3. 项目数据范围在查询、统计、Agent回答和详情接口中统一生效。
4. 风险管理员只能配置自己的邮箱。
5. 系统管理员可查看邮箱连接状态，但不得查看授权码或代配个人邮箱。
6. API Key 和 Excel 导入权限默认只授予系统管理员。
7. 查看/审计员不得执行上报、解除、导入、配置和密钥操作。

### 3.3 项目数据范围

| 范围类型 | 说明 |
|---|---|
| 全部项目 | 可访问系统当前全部有效项目 |
| 本人负责项目 | 按项目负责人字段自动确定 |
| 指定部门 | 可访问选定部门下的项目 |
| 指定项目 | 按项目 ID 逐项授权 |
| 本人负责及授权项目 | 本人负责项目与人工授权项目的并集 |

## 4. 全局页面与交互规范

### 4.1 视觉方向

1. 采用“清透科技”视觉体系。
2. 业务端使用浅蓝背景、蓝青渐变和白色内容卡片。
3. 管理后台使用固定侧栏、顶部工具栏和白色管理卡片。
4. 高风险使用红色，中风险使用橙色，低风险或成功使用绿色。
5. 金额、比例、状态和时间使用统一格式，不在不同页面改变含义。

### 4.2 字体与可读性

1. 所有后台管理页面可见文字最小字号不得小于 12px。
2. 所有详情弹框可见文字最小字号不得小于 12px。
3. 弹框普通详情正文建议 14px 至 15px。
4. 关键金额使用 17px 至 19px并加粗。
5. 待回款关键金额使用红色粗体。
6. 按钮文字必须单行展示，不允许“编辑”“测试连接”等中文逐字换行。
7. 表格辅助文字和状态徽标不得因响应式压缩低于 12px。

### 4.3 通用控件

1. 搜索框支持输入即时筛选。
2. 自定义下拉支持鼠标、触屏和键盘操作。
3. 下拉菜单支持上下方向键、Home、End、Enter、Space、Escape和Tab。
4. 下拉选中项显示勾选状态。
5. 重置按钮恢复全部筛选项和搜索条件。
6. 密码、授权码和 API Key 输入支持临时显示，但默认隐藏。
7. 输入错误在字段附近显示，不仅依赖顶部提示。

### 4.4 弹框、抽屉和反馈

1. 详情弹框支持关闭按钮、遮罩点击和 Escape 关闭。
2. 右侧抽屉用于复杂编辑或完整详情。
3. 危险操作使用二次确认弹框。
4. 提交过程中按钮显示加载状态并防止重复提交。
5. 操作结果使用页面提示或 Toast 反馈。
6. 关闭后焦点返回触发操作的控件。
7. 弹框内容不得为了适配屏幕而删减。

### 4.5 数据格式

| 数据类型 | 格式 |
|---|---|
| 金额 | 页面统一显示万元，带千分位，通常保留两位小数 |
| 原始金额 | Excel按元解析和入库 |
| 比例 | 保留一位小数并显示 `%` |
| 日期 | `YYYY-MM-DD` |
| 日期时间 | `YYYY-MM-DD HH:mm` |
| 批次号 | `IMP-YYYYMMDD-序号` 或 `SYNC-YYYYMMDD-HHmm` |
| Trace ID | 可复制，详情和审计中完整展示 |

### 4.6 响应式规范

1. 所有页面最低支持 320px 宽度。
2. 登录页使用 1100px、820px、520px 分级适配。
3. Web风险看板使用 1260px、900px、680px 分级适配。
4. 看板在 900px 及以下将风险清单由多列表格改为卡片。
5. 看板在 680px 及以下使用更紧凑的两列风险卡片布局。
6. 风险卡片必须完整展示等级、项目、负责人、类别、描述、上报来源和周次。
7. 业务端手机底部固定保留 Web 风险看板和 Agent 智能对话入口。
8. 后台宽表格可横向滚动，但不得压缩到逐字换行。
9. 手机端 Agent 使用全屏或接近全屏抽屉。

## 5. 第01页：登录

### 5.1 页面目的

为所有角色提供统一的账号密码登录入口，并按角色进入业务端或管理后台。

### 5.2 页面字段

| 字段 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| 账号 | 文本 | 是 | 去除首尾空格；正式系统校验账号状态 |
| 密码 | 密码 | 是 | 默认掩码；支持显示/隐藏 |
| 记住账号 | 复选框 | 否 | 仅保存账号，不保存密码 |

### 5.3 操作

1. 登录。
2. 忘记密码。
3. 显示或隐藏密码。
4. 记住账号。

### 5.4 校验与状态

1. 账号为空时提示“请输入账号”。
2. 密码为空时提示“请输入密码”。
3. 提交期间登录按钮不可重复点击。
4. 账号停用、锁定或密码错误时显示明确原因。
5. 首次登录用户进入修改初始密码流程。
6. 忘记密码弹框说明联系系统管理员重置。

### 5.5 跳转规则

1. 系统管理员登录后进入第03页。
2. 风险管理员、项目经理和查看/审计员进入第02页。
3. 正式系统必须以服务端角色为准，不使用原型账号字符串判断。

### 5.6 验收标准

1. 必填校验、密码显隐和记住账号有效。
2. 失败登录不创建有效会话。
3. 登录成功后菜单与接口权限一致。
4. 320px宽度下不出现横向滚动。

## 6. 第02页：Web风险看板

### 6.1 页面目的

统一展示风险、项目、回款、待办、时间线、已解除风险和周报信息，并提供 Agent 智能查询入口。

### 6.2 顶部导航

1. 品牌标识和当前版本。
2. Web 风险看板入口。
3. Agent 智能对话入口。
4. 通知按钮。
5. 当前用户和数据范围。
6. 风险管理员菜单：个人邮箱配置、邮箱同步结果、修改密码、退出登录。
7. 项目经理和查看/审计员不显示邮箱配置入口。

### 6.3 页面标题区

1. 标题：Web 风险看板。
2. 副标题说明数据来自项目清单、回款数据和周报线索。
3. 显示最近更新时间。
4. “刷新数据”重新获取统计、列表和同步状态。

### 6.4 顶部统计卡

| 卡片 | 指标 | 计算/说明 |
|---|---|---|
| 项目总数 | 当前有效在交付项目数 | 来自最新成功Excel批次 |
| 风险总数 | 当前有效风险数 | 周报提取与日常上报合并 |
| 高风险 | 当前高风险数 | 按最新风险等级统计 |
| 待回款金额 | 风险项目剩余待回款 | 只统计存在有效风险的项目 |
| 已回款 | 风险项目实际已回款 | 只统计存在有效风险的项目 |

点击卡片打开对应详情弹框。弹框必须显示数据来源、统计口径和更新时间。

### 6.5 本周重点关注

1. 展示高风险、本周新增和持续未解除风险。
2. 每项包含等级、项目名称和完整摘要。
3. 默认按风险等级、待回款金额和更新时间排序。
4. 点击后打开完整风险详情。
5. 周报同步、日常上报和解除后自动更新。

### 6.6 六个业务页签

页签固定为：

1. 项目风险清单。
2. 部门回款汇总。
3. 管理者待办。
4. 应收与回款。
5. 风险时间线。
6. 已解除风险。

手机端允许横向滚动，但不得删除页签。

### 6.7 项目风险清单

#### 6.7.1 筛选条件

| 控件 | 规则 |
|---|---|
| 搜索 | 匹配项目名称或风险描述 |
| 风险等级 | 全部、高风险、中风险、低风险 |
| 风险类别 | 根据系统配置动态生成 |
| 负责人 | 根据有权限的数据动态生成 |
| 重置 | 清空搜索并恢复全部筛选 |

#### 6.7.2 列表字段

1. 风险等级。
2. 项目名称。
3. 项目负责人。
4. 风险类别。
5. 完整风险描述。
6. 上报人。
7. 来源：周报 AI 提炼或日常上报。
8. 周次。

#### 6.7.3 手机端卡片

1. 900px及以下切换为卡片，不继续压缩桌面表格。
2. 680px及以下使用两列网格区域。
3. 项目名称、类别和描述允许自然换行，禁止逐字竖排。
4. 卡片文字最小 12px。
5. 卡片整体可点击并支持键盘焦点。

### 6.8 风险详情弹框

风险详情不得删减，至少包含：

1. 风险编号。
2. 来源。
3. 周次。
4. 状态。
5. 更新时间。
6. 风险等级。
7. 关联项目。
8. 风险类别。
9. 上报人。
10. 完整风险描述。
11. 完整证据或信息来源。
12. 完整建议措施。
13. 关联行动项：紧急度、事项、负责人、类型。
14. 同项目其他风险。
15. 数据来源说明。

同项目风险卡片可切换到对应风险详情。

### 6.9 部门回款汇总

| 字段 | 说明 |
|---|---|
| 部门 | 交付部门 |
| 计划回款 | 部门项目计划回款合计 |
| 已回款 | 实际已回款合计 |
| 剩余待回款 | 剩余待回款合计 |
| 完成率 | 已回款/计划回款 |

部门详情弹框显示计划回款、已回款、完成率、剩余待回款、数据来源和更新时间。剩余待回款使用 19px 红色粗体。

### 6.10 管理者待办

1. 展示紧急度、项目、完整待办事项、负责人和类型。
2. 支持按负责人筛选。
3. 点击打开待办详情。
4. 本周日程建议显示周一、周二、周三和周五前等安排。
5. 日程文字不得小于 12px。
6. 风险解除后更新关联待办状态。

### 6.11 应收与回款

| 字段 | 说明 |
|---|---|
| 项目 | 当前存在风险的项目 |
| 计划金额 | 年度计划或合同口径金额 |
| 已回款 | 实际已回款 |
| 待回款 | 当前剩余待回款 |
| 下一笔回款 | 月份、节点和金额 |
| 进度 | 完成率和进度条 |

项目回款详情弹框必须与部门回款详情采用一致字体层级。待回款金额使用 19px 红色粗体；下一笔回款和统计口径不得删减。

### 6.12 风险时间线

1. 按日期展示新增、持续、缓解和解除事件。
2. 显示事件标题、说明、状态和风险颜色。
3. 点击打开时间线详情。
4. 日常上报、等级变化和解除自动生成事件。

### 6.13 已解除风险

展示风险描述、项目、原等级、原类别、解除时间和解除原因。通过 Agent 解除的风险自动进入该列表。

### 6.14 本周周报邮件汇总

| 字段 | 说明 |
|---|---|
| 同步状态 | 分析完成、分析中、失败等 |
| 发件人 | 周报发送人 |
| 日期 | 邮件发送日期 |
| 涉及项目 | 模糊匹配后的标准项目 |
| 关键要点 | AI提炼的完整要点 |

“同步周报”触发邮箱同步流程。无邮箱配置时引导风险管理员进入第10页。

### 6.15 周报详情弹框

不得删减以下内容：

1. 发件人。
2. 发送日期。
3. 涉及项目数量。
4. 同步状态。
5. AI分析状态。
6. 完整关键要点。
7. 涉及项目列表和当前风险状态。
8. 全部提取风险。
9. 关联行动项。
10. 数据来源。

提取风险可点击进入对应风险详情。

### 6.16 Agent智能对话

#### 6.16.1 支持意图

1. 查询全部高风险。
2. 查询指定项目风险。
3. 查询指定负责人风险。
4. 查询风险项目回款。
5. 查询管理者待办。
6. 查询周报摘要。
7. 日常上报风险。
8. 解除风险。
9. 获取帮助示例。

#### 6.16.2 交互规则

1. 桌面端使用右侧抽屉。
2. 手机端使用全屏或接近全屏布局。
3. 支持快捷问题和文本输入。
4. Enter发送，Shift+Enter换行。
5. 回答必须受项目数据权限控制。
6. 回款回答包含金额、比例、项目和数据时间。
7. 上报和解除属于写操作，提交前需要明确确认。
8. AI未配置、超时或失败时显示原因和重试入口。

#### 15.3.2 列表字段

1. 处理状态。
2. 邮件主题和发件人。
3. 发送时间。
4. 匹配项目。
5. 风险线索。
6. 处理结果。

### 15.4 同步批次页签

展示批次编号、触发方式、开始时间、执行用时、扫描/新增、风险线索和结果。

### 15.5 邮件详情抽屉

不得删减以下内容：

1. 处理状态。
2. 同步批次。
3. 邮件时间。
4. 关键要点。
5. 项目匹配结果和置信度。
6. 风险类别、等级、证据、建议和处理说明。
7. 附件。
8. 失败原因。
9. 完整处理轨迹。
10. 忽略、调整后确认、确认发布或失败重试操作。

### 15.6 重试和同步

1. 失败邮件支持重新处理。
2. 重试成功后更新邮件状态并生成风险线索。
3. 手动同步显示进度弹框和结果。
4. 重复邮件按唯一标识跳过。
5. 不符合规则邮件标记跳过并说明原因。

### 15.7 验收标准

1. 邮件和批次两个页签切换正确。
2. 搜索、状态、批次筛选和重置有效。
3. 邮件详情完整。
4. 失败重试能更新状态和风险线索。
5. 可返回邮箱配置和风险看板。

## 16. 跨页面业务流程

### 16.1 登录与权限流程

1. 用户提交账号密码。
2. 服务端验证账号、密码、状态和锁定情况。
3. 创建服务端会话并写入安全Cookie。
4. 返回用户角色、权限和数据范围。
5. 前端按权限进入业务端或后台。
6. 每次接口请求再次鉴权。

### 16.2 用户授权流程

1. 系统管理员创建用户。
2. 分配角色和项目范围。
3. 用户首次登录修改密码。
4. 用户进入看板后只看到授权项目。
5. 权限变更后原会话按策略刷新或失效。

### 16.3 Excel数据生效流程

1. 上传Excel。
2. 解析工作表。
3. 校验字段和金额。
4. 匹配项目。
5. 处理警告和歧义。
6. 发布批次。
7. 刷新项目、回款和看板。
8. Agent使用最新成功版本。

### 16.4 邮箱同步与风险生成流程

1. 风险管理员保存个人邮箱。
2. 手动或定时触发同步。
3. 系统增量读取符合规则的邮件。
4. 提取正文和受支持附件。
5. 识别项目并执行AI风险提取。
6. 高置信风险按规则进入风险清单；低置信结果待确认。
7. 更新周报汇总、统计和重点关注。
8. 记录同步和审计日志。

### 16.5 日常上报与解除流程

1. 项目经理在Agent中描述风险或解除原因。
2. Agent识别项目、类别、等级和意图。
3. 用户确认写操作。
4. 服务端校验项目权限。
5. 保存风险或解除记录。
6. 更新清单、统计、时间线、已解除风险和待办。
7. 写入审计日志。

## 17. 数据口径与业务规则

### 17.1 项目

1. 项目使用系统内部ID作为正式关联键。
2. Excel项目编码是优先匹配字段，不是强制主键。
3. 项目名称、部门和负责人用于无编码项目的组合匹配。
4. 项目别名用于周报和Agent识别。
5. 新批次未出现的历史项目不自动删除。

### 17.2 风险

1. 风险来源分为周报AI提炼和日常上报。
2. 风险等级为高、中、低。
3. 风险状态至少包含新增、持续、缓解和解除。
4. 解除必须记录解除人、时间和原因。
5. 同一项目可存在多个不同类别风险。
6. 风险详情保留证据、建议和关联行动项。

### 17.3 回款

1. 看板风险项目待回款只统计存在有效风险的项目。
2. 空金额不按0计算。
3. 部门汇总来自项目明细重新计算。
4. 完成率为已回款除以计划金额。
5. 计划金额为0或空时不计算误导性百分比。
6. 下一笔回款来自月度预计或计划节点。

### 17.4 周报

1. 邮件以消息ID、邮箱和附件摘要等组合去重。
2. 显式风险标记优先保留原文。
3. 未明确写“风险”的问题描述仍可提取隐含风险。
4. 项目匹配置信度不足时不得自动错误关联。

## 19. 安全与审计要求

### 19.1 身份与会话

1. 使用服务端会话和HttpOnly Cookie。
2. 密码使用Argon2id等安全算法。
3. 登录失败达到阈值后锁定。
4. 修改密码、停用账号和高风险权限变更使相关会话失效。
5. 写操作防止CSRF和重复提交。

### 19.2 敏感数据

1. 邮箱授权码和API Key使用AES-256-GCM等方式加密。
2. 页面和接口不回显完整敏感值。
3. 日志统一脱敏。
4. Excel原文件下载受系统管理员权限控制。
5. AI输入应去除无关个人信息和系统密钥。

### 19.3 审计事件

必须记录：

1. 登录、退出和失败。
2. 用户、角色、权限和数据范围变更。
3. Excel上传、校验、发布、失败和回滚。
4. 邮箱配置、测试、同步、重试和停用。
5. API服务新增、测试、轮换、切换默认和停用。
6. 系统配置发布。
7. 风险上报、修改和解除。
8. 审计日志导出。

## 22. 验收测试总表

### 22.1 功能验收

1. 11个页面可按角色从登录页进入。
2. 业务端和后台端导航闭环。
3. 用户、角色和项目范围真实持久化。
4. 当前Excel样表可导入、预览、发布和回滚。
5. 邮箱可测试、保存、同步和停用。
6. 周报可生成项目匹配和风险线索。
7. 看板统计与最新成功数据一致。
8. Agent查询、上报和解除受权限控制。
9. API Key不明文展示。
10. 审计事件完整可追溯。

### 22.2 界面验收

1. 后台和详情弹框最小字号不小于12px。
2. 风险和周报详情内容完整。
3. 待回款金额红色加粗。
4. 用户表单姓名和登录账号严格对齐。
5. 用户列表“编辑”按钮不换行。
6. 邮箱配置三个操作按钮同一行且不换行。
7. 手机风险清单使用卡片且不变形。
8. 320px至桌面宽度无关键内容丢失。

### 22.3 安全验收

1. 未授权页面和接口不可访问。
2. 密码、授权码和API Key不进入响应和日志。
3. Excel错误批次不生效。
4. 写操作防重复提交。
5. 审计日志不可普通修改和删除。

### 22.4 数据核对

1. 项目数与最新有效主清单一致。
2. 风险数、高风险数与有效风险一致。
3. 风险项目回款口径不混入无风险项目。
4. 部门汇总等于项目明细汇总。
5. 空金额保持未知。
6. 回滚后数据版本和统计一致。

## 23. 原型与正式实现边界

当前 HTML 原型已经确认页面结构、字段、交互和视觉规范，但以下能力仍需正式开发：

1. 真实登录、会话、锁定和密码策略。
2. 用户、角色、权限和项目范围数据库持久化。
3. Excel文件解析、校验、事务发布和回滚。
4. IMAP连接、邮件增量同步、附件解析和去重。
5. AI风险提取、项目匹配和Agent服务端查询。
6. API Key加密存储和真实连接测试。
7. 审计日志写入、检索和导出。
8. 看板真实数据接口和缓存刷新。

正式开发必须保留当前11页原型作为视觉和交互基线，不得直接把原型中的模拟数据或前端判断当作生产逻辑。
