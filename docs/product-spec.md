# 产品规格

## 产品目标

平台汇集项目清单、应收回款、周报和日常上报中的风险信息，为管理者提供统一的风险跟踪、处置和查询视图。核心入口是 Web 风险看板和 Agent 智能对话，后台管理、邮箱同步和周报处理为其提供支撑。

## 核心术语

- **项目**：平台关联风险、回款、周报和待办的标准业务对象。
- **项目别名**：自然语言、历史名称或周报中对标准项目的其他指代。
- **风险**：已经进入正式风险清单的潜在损失、问题或不确定事项。
- **跟踪中风险**：仍需持续关注的正式风险。
- **已解除风险**：已消除或不再需要跟踪的风险；再次出现时可以重新打开。
- **风险候选**：从周报等来源提取、尚未由人员确认进入正式风险清单的线索。
- **管理者待办**：由风险产生并推动处置的行动事项。
- **项目数据范围**：用户可访问的项目集合，只能是全部、本人负责、指定项目、本人负责及指定项目，或无项目权限。

## 角色与访问

系统管理员负责用户、角色和系统配置；风险管理员负责项目导入、邮箱/周报和风险运营；项目经理处理其项目范围内风险和待办；查看者/审计角色按授权范围只读访问。任何 API、Agent 工具和后台任务都必须遵守相同的权限与项目范围规则。

## 项目与 Excel 导入

项目拥有内部不可变 ID。外部项目编码并非所有数据源都存在，因此不能作为必填唯一键。

匹配顺序：存在项目编码时优先使用规范化编码；否则使用规范化项目名、部门、负责人等形成候选。名称重复、信息不足或多候选时必须进入管理员确认，禁止自动合并。

金额统一按“元”存储；界面可以换算为“万元”。空金额表示未知/缺失，不等于零。月份字段从表头动态识别，不能硬编码固定月份。汇总页属于派生展示，不作为事实数据导入。

标准导入流程：上传并计算摘要 → 识别结构 → 解析 → 匹配/去重/校验 → 预览 → 管理员处理歧义 → 事务提交 → 保存文件摘要、映射、日志与提交前快照 → 刷新派生数据。已提交批次必须支持经授权的回滚。

## 风险、待办与时间线

风险正式生命周期保持 `ACTIVE` / `RESOLVED` 两态语义。处置措施或待办状态不改变风险是否仍需跟踪。风险状态变化、关键处置和审计事件进入时间线；已解除风险仍可查询并在再次出现时重新打开。

## 周报与邮箱

周报来自风险管理员邮箱同步，可包含正文和批准类型的附件。系统尽量少保留原始邮件内容，并遵守附件安全、留存和删除策略。

“本周周报”按上海时区本周一 00:00 至下周一 00:00 判断；优先使用邮件发送时间，缺失时使用接收时间。延迟同步不改变周报所属周。

AI 可辅助提取项目、风险候选和结构化内容，但人工确认、权限和审计边界不能被 AI 绕过。

## Agent 智能对话

Agent 用于查询项目业务信息，以及上报、处理或解除风险。Agent 不是通用聊天机器人，也没有任意 shell 或数据库权限。

只允许调用注册且批准的业务工具。读取必须受用户权限和项目范围约束；持久化写入必须先形成明确提案，并在用户显式确认后执行。流式响应通过 SSE 传递，失败、取消和恢复必须保持可判定状态。

## 非目标

当前架构不引入微服务、Kafka、Kubernetes、多数据库、双后端或双写迁移体系；历史 NestJS/Prisma 代码不属于正式产品运行时。
